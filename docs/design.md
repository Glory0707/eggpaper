# eggpaper 项目设计

> v0.3 · 2026-09-11（已实现能力移至 [README](../README.md)，本文只保留定位、原则、取舍与未竟事项）

## 1. 一句话定位

**本地优先、轻量的科研文献阅读器：术语一致的翻译 + 从作者写作意图解析论文的论证骨架。**

四个差异点：

1. **本地优先** —— 文献、术语表、标注、笔记全部留在本机。
2. **无账号无订阅** —— LLM 用自己的 key（任意 OpenAI 兼容端点），一篇成本毛钱级。
3. **术语一致** —— 一份术语表贯穿划词 / 段译 / 整本 / 总结 / 问答。
4. **论证骨架 + 眉批** —— 核心差异化（argumentative zoning / rhetorical roles 的产品化，市面空白）。

已实现能力清单见 [README](../README.md)；交互设计见 [ux.md](ux.md)；视觉与动效 token 见 [visual.md](visual.md)；实施状态见 [plan.md](plan.md)。

## 2. 设计原则

1. **本地优先**：数据只在本地；唯一出网是用户配置的 LLM/翻译服务。
2. **无账号**。
3. **术语贯穿**：一份术语表约束所有 AI 输出。
4. **可溯源**：一切 AI 结论给出依据（¶编号/矩形锚点），点击跳回。
5. **推断可纠正**：角色是推断不是判定；改判持久化、可回退。
6. **界面减法**：不放解释性小字；功能自明；同一信息只出现一处。判断标准——删掉这行字，用户会损失什么？没损失就删。
7. **做减法**：每轮规划先问"哪些该砍"。

## 3. 砍掉清单（防复活）

| 砍掉项 | 理由 |
|---|---|
| 略读联动翻译省 token | 整本翻译三模式已覆盖其价值 |
| 查词自动沉淀术语 | 自动加入=噪音；一键收进已是最低摩擦 |
| 云同步 / 账号 / 社区 | 与本地优先定位冲突 |
| 文献管理功能 | Zotero 已够（拖拽导入天然兼容），对接不做替代 |
| 写作润色 | 红海，且不在阅读动线上 |
| 多论文并读 / 深色模式 / 段内术语悬停 | 见 ux.md §7，违背单锚点深读或收益过低（**缩论文正文字号**同样不做；界面字号可调，已实现） |

## 5. 架构（已验证）

```
浏览器 UI（Vue3 + pdf.js，Inter + JetBrains Mono 两声字体，Fraunces 只署 wordmark）
        │ localhost
FastAPI：解析(PyMuPDF) · 骨架/眉批/总结/问答/推荐问题(LLM 适配器) ·
        翻译调度(pdf2zh subprocess) · SQLite
        │ 出网仅两类
LLM API（OpenAI 兼容） · pdf2zh 翻译服务（google/bing/deepl/…）
```

工程纪律：外部引擎一律 subprocess 不 import（AGPL 边界）；单篇长上下文直塞不引入向量库；LLM 输出归一化校验（键/枚举/范围），失败报错不静默；空响应自动加倍重试（推理模型 token 预算）；动效只动 opacity/transform，尊重 prefers-reduced-motion。

## 6. 验证基线（实测记录）

真实双栏 DFT 论文（arXiv:2609.06350，9 页）实测：解析 23 段全对；骨架主张无遗漏、角色 100% 覆盖；眉批 18 条 100% 锚定；划词术语命中 4/4；整本双语（bing）成功；走查协议 5 项 PASS；推荐问题达审稿人水准（ZPE 修正/微观可逆性/Bader 证据/(110) 暴露度）。角色判断为推断，跨学科需调 prompt。

## 7. 已知限制

- pdf2zh 经典版（1.9.x）不支持 glossary 参数：整本翻译的术语锁定暂缺，其余四条链已覆盖
- 解析器针对双栏英文排版调校；单栏/其他排版遇到再修
- 骨架/眉批 prompt 按化学定制，扩展学科需做成可配置模板

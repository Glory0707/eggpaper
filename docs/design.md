# eggpaper 项目设计

> 剥开论文的壳，读论证的芯。Crack the paper, read the marrow.
> v0.2 · 2026-09-11（MVP 已验证后全量修订：砍掉伪需求，明确翻译三模式与界面减法）

---

## 1. 一句话定位

**本地优先、轻量的科研文献阅读器：术语一致的翻译 + 从作者写作意图解析论文的论证骨架。**

四个差异点：

1. **本地优先** —— 文献、术语表、标注、笔记全部留在本机。评审稿件、未发表手稿也能读。
2. **无账号无订阅** —— LLM 用自己的 key（任意 OpenAI 兼容端点），一篇论文成本毛钱级。
3. **术语一致** —— 一份术语表贯穿翻译、总结、问答、整本翻译四条链路。
4. **论证骨架 + 眉批** —— 核心差异化：主张/证据/对照/样板段的角色体系 + 句级人性化批注（妥协/凑字数/生硬/多余/吹嘘/AI 痕迹）。学术上对应 argumentative zoning / rhetorical roles，市面空白。

## 2. 竞品与空位（结论保留）

小绿鲸/知云/ReadPaper = 云端、订阅、重；pdf2zh = 只有翻译没有阅读环境；ChatPDF 类 = 贵且不可溯源。
空位 = **本地轻量壳 + 术语全链一致 + 论证骨架**。骨架层学术活跃（argumentative zoning）而无产品化；眉批层（句级人性化批注）连学术原型都少。

## 3. 设计原则

1. **本地优先**：数据只在本地；唯一出网是用户配置的 LLM/翻译服务。
2. **无账号**。
3. **术语贯穿**：一份术语表约束翻译 / 总结 / 问答 / 整本翻译（pdf2zh glossary 文件）。
4. **可溯源**：一切 AI 结论给出依据（¶编号/矩形锚点），点击跳回。
5. **推断可纠正**：角色是推断不是判定；用户改判持久化。
6. **界面减法**（v0.2 新增）：不放解释性小字；功能自明；同一信息只出现一处；装饰性文案一律删。判断标准——删掉这行字，用户会损失什么？没损失就删。
7. **做减法**：不做文献管理替代、不做社区、不做云同步；每轮规划先问"哪些该砍"。

## 4. 功能全景（v0.2，按状态分档）

### ✅ 已实现（MVP，已在真实双栏 DFT 论文上验证）

| 功能 | 说明 |
|---|---|
| 导入与解析 | 拖入/点击导入；行级双栏重建；参考文献/补充材料/作者块/图注自动排除 |
| 论证骨架 | 主张→证据链树；八类角色页边标签；目的批注；改判持久化 |
| 眉批 | 句级人性化批注（hedge/padding/stiff/redundant/hype/ai/insight/warning），楷体页边展示，原文矩形高亮 |
| 略读模式 | 非核心段蒙纱、核心段琥珀条（纯阅读聚焦工具，不再联动翻译） |
| 划词/段落翻译 | 整段上下文 + 术语表锁定；划词气泡一键收进术语表 |
| 问答 | 长上下文直塞（无 RAG）；¶引用内联可跳转 |
| 一眼卡 | 一句话 + 贡献/方法/发现 + 关键词 |
| 整本双语 | pdf2zh subprocess 隔离调用；双语文档原文/译文交替 |
| 术语本 | 种子包 + 手动增删 + 筛选 |
| 本地设置 | 任意 OpenAI 兼容端点；连接测试；演示模式 |

| 模式 | 内容 | 实现 |

**T2 界面减法**：删 colophon 页脚、删左栏底部小字、删顶栏装饰性 vol 文案、文档元信息去掉文件名、角色图例只显示非零项、推断免责声明移进角色卡内部。原则见设计原则 6。

**T3 一致性补漏**：术语表注入问答与总结的 system prompt；术语表导出 csv 同步给 pdf2zh `--glossary-files`，整本翻译也锁译法。

**T4 功能走查**：见 plan.md 的走查协议——每个功能按脚本实测顺手度，不顺手的改或砍。

### P2 · 排队

- **方法卡片**：Methods 抽成"材料+参数+步骤"protocol 卡（模式与一眼卡同，成本低，实验学科价值高）
- **本文缩写**：骨架分析顺带抽取缩写首现展开表，进术语 tab 并可一键入术语表
- **图表速览**：按版面区域抽出 Figure 1–N 连图注成画廊（注意矢量图的区域渲染方案）
- **Markdown 导出**：骨架+眉批+一眼卡+关键译文组装成 .md，回 Zotero/Obsidian
- **术语导出**：CSV / Anki
- **实验映射增强**：每个证据锚点补"回答什么问题"字段（骨架 prompt 加一列）
- **框选区域视觉问答**：框选公式/表格直接问"这两步怎么推的"——依赖接入视觉模型（可配置 second model），到时再做

### P3 · 缓存（真实但不急）

数据对比表（跨文献抽数值，工程大频率低）· 批量速览（组会场景）· 审稿模式 · Zotero 深度集成（拖拽导入已天然兼容）· Tauri 打包 · OCR 扫描件

### ❌ 砍掉（防复活清单）

| 砍掉项 | 理由 |
|---|---|
| 略读联动翻译省 token | 整本翻译三模式已覆盖其价值 |
| 查词自动沉淀术语 | 自动加入=噪音；一键收进已是最低摩擦 |
| 云同步 / 账号 / 社区 | 与本地优先定位冲突 |
| 文献管理功能 | Zotero 已够，对接不做替代 |
| 写作润色 | 红海，且不在阅读动线上 |

## 5. 架构（不变，已验证）

```
浏览器 UI（Vue3 + pdf.js）／可选 Tauri 壳
        │ localhost
FastAPI：解析(PyMuPDF) · 骨架/眉批/总结/问答(LLM 适配器) · 翻译调度(pdf2zh subprocess) · SQLite
        │ 出网仅两类
LLM API（OpenAI 兼容） · pdf2zh 翻译服务（google/bing/deepl/…）
```

要点：外部引擎一律 subprocess 不 import（AGPL 边界）；单篇长上下文直塞不引入向量库；LLM 输出做归一化校验（键/枚举/范围），失败报错不静默；推理型模型 max_tokens 需留足思考额度。

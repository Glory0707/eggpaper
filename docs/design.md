# eggpaper 项目设计

> 剥开论文的壳，读论证的芯。Crack the paper, read the marrow.
> v0.1 设计定稿 · 2026-09-11

---

## 1. 一句话定位

**本地优先、轻量的科研文献阅读器：术语一致的翻译 + 从作者写作意图解析论文的论证骨架。**

四个差异点，也是对现有所有工具的正面回答：

1. **本地优先** —— 文献、术语表、标注、笔记全部留在本机。评审稿件、组内未发表手稿也能放心读。
2. **无账号无订阅** —— 不注册、不登录，LLM 用自己的 API key（DeepSeek/GLM/任意 OpenAI 兼容端点，含本地 ollama），一篇论文成本毛钱级。
3. **术语一致** —— 一份个人术语表贯穿翻译、总结、问答全链路，读得越多表越准。
4. **论证骨架** —— 核心差异化：告诉读者哪个实验是核心证据、哪个只是对照、哪段是标准流程样板、作者在哪里心虚。学术上对应 argumentative zoning / rhetorical roles（研究活跃、无产品化），是市面空白。

## 2. 背景与竞品

| 工具 | 强项 | 短板 |
|---|---|---|
| 小绿鲸 | 学科词库大、AI 解析、笔记模板，功能最全 | 云端网盘制、功能过重、订阅付费、文献要上传 |
| 知云 | 免费、划词+整篇翻译、分栏对照、术语库 | 账号登录、AI 能力弱 |
| 沉浸式翻译 / pdf2zh (BabelDOC) | 整本双语、公式排版保留、开源、支持术语表 | 只有翻译，没有阅读环境、问答、笔记 |
| ReadPaper / SciSpace / ChatPDF | PDF 问答、结构化总结 | 通用订阅制、贵、与翻译割裂、不可溯源审校 |

结论：**"翻译好"的开源引擎已有（pdf2zh，EMNLP 2025），"问答总结"是长上下文 LLM 皆能之事。缺的是一个把它们串起来、文献不出本机的轻量壳，以及无人做过的论证骨架。**

## 3. 目标用户与场景

- 首批用户：化学/材料方向研究生与科研人员（作者本人 dogfood，角色体系按化学/论文结构定制，后续做成可配置模板扩展学科）。
- 工作流三段：
  - **读前筛选**：决定要不要精读（一眼卡、图表速览、批量模式）。
  - **读中理解**：核心场景（双语对照、划词、骨架、框选公式提问、方法卡片）。
  - **读后沉淀**：黏性来源（术语本、对比表、笔记导出）。
- 隐私场景：审稿稿件、未发表数据不能上云——这是本地优先的直接价值。

## 4. 设计原则

1. **本地优先**：数据只在本地 SQLite/文件；唯一出网是用户配置的 LLM API 调用，UI 明示。
2. **无账号**：无注册无云同步；数据目录用户可指定。
3. **术语贯穿**：一份术语表约束所有 LLM 调用（翻译/总结/问答/骨架），阅读中查过的词自动沉淀。
4. **可溯源**：一切 AI 结论（骨架、问答、总结）必须给出依据句/页码，点击跳回原文。答案不可核查即负资产。
5. **推断可纠正**：骨架角色是"推断"不是"判定"；用户可改判，改判持久化并被后续参考。
6. **做减法**：不做文献管理（对接 Zotero 即可）、不做社区、不做云同步、OCR 后置。

## 5. 功能全景

### A. 翻译底座（P0）

| 编号 | 功能 | 说明 |
|---|---|---|
| A1 | 整本双语对照 | pdf2zh 引擎（subprocess 调用），排版/公式/多栏保留 |
| A2 | 划词翻译 | 整段上下文注入 prompt + 术语表锁定译法 |
| A3 | 术语系统 | 手动术语表 + 自动沉淀；学科 prompt：化学式/单位不译、缩写首现展开、IUPAC 命名规范 |

### B. 论证骨架（P1，差异化核心）

- **B1 骨架侧栏**（常驻树视图）：

```
研究缺口：现有膜材料选择性-渗透率 trade-off 未突破（¶1 末）
├─ 核心主张 C1：引入刚性单元打破 trade-off
│   ├─ 关键证据：Fig 3 主实验（¶3.2）
│   └─ 对照/参比：空白膜、商用膜对比（¶3.3，仅为严谨）
├─ 核心主张 C2：机理是 XXX
│   ├─ 关键证据：Fig 5 表征 + DFT（¶3.5）
│   └─ 薄弱处：DFT 只算了一个模型体系（审稿人视角）
└─ 承认的局限：长期稳定性未测（¶5）
```

- **B2 段落角色标注 + 句级透镜**：页边彩色标签；hover 任意句子显示"这句话在干什么"（如"预告对照样品的必要性""主动承认产率低以堵审稿人"）。
- **B3 略读模式**：按角色过滤——只展开缺口+主张+关键证据+局限，其余折叠；翻译联动只译骨架段（30 页论文核心常只有 3 页，token 与时间同省 ~70%）。
- **B4 实验-论点映射表**：每个实验回答什么问题 / 核心还是对照 / 支撑哪条主张 / 删掉还成立吗。组会讲文献直接照讲。
- **B5 审稿模式**（P2）：从证据链薄弱处自动起草 weakness 列表。

**角色 taxonomy（v1，化学/材料定制）**：

| 角色 | 含义 | 典型信号 |
|---|---|---|
| 背景铺垫 background | 领域常识铺垫，可跳过 | 领域综述句式 |
| 缺口转折 gap | 作者真正的出发点 | "however / remains challenging" |
| 核心主张 claim | 论文要证明的命题 | "we demonstrate / propose" |
| 关键证据 evidence | 核心实验 | 主结果图/表 |
| 对照参比 control | 仅为严谨 | blank/商用对照 |
| 标准流程描述 boilerplate | 表征条件、标准步骤（样板段） | XRD/SEM/测试条件 |
| 参数优化/拓展 extension | 锦上添花 | "further / moreover" |
| 让步/局限 limitation | 作者自己心虚处 | hedging 句式 |

**可靠性三底线**：每个标签可点开看依据句（溯源）；用户改判持久化；UI 措辞用"推断"而非"判定"，样板段用中性词（不叫"凑字数"）。

### C. 问答与总结（P1.5）

- **C1 三卡**：一眼卡（一句话结论+贡献/方法/结论三行）｜方法卡（材料+参数+步骤的可复现 protocol）｜图表速览（Fig 1–N 连图注）。
- **C2 单篇问答**：全文直塞长上下文（单篇不需要 RAG/向量库）；答案带页码溯源 + 段落角色标签；支持按角色提问（"只基于核心证据回答"）。
- **C3 多篇对比**（P2）：从多篇抽取数值生成横向对比表。

### D. 沉淀与集成（P2）

- **D1** 术语本导出（CSV/Anki）
- **D2** Markdown 笔记导出（含双语关键句）
- **D3** Zotero 对接（导入导出，不做文献管理替代）

### 明确不做

文献管理替代、社区、写作润色、云同步、团队协作、扫描件 OCR（v1 后置）。

## 6. 架构与技术栈

```
┌──────────────────────────────────────────┐
│  UI：浏览器（可选 Tauri 壳打包，<20MB）      │
│  pdf.js 阅读器 + 骨架侧栏 + 问答面板 + 术语本 │
└───────────────┬──────────────────────────┘
                │ HTTP (localhost)
┌───────────────┴──────────────────────────┐
│  本地服务：Python + FastAPI                │
│  · 版面解析 PyMuPDF（段落文本 + bbox 坐标） │
│  · 翻译调度 → pdf2zh（subprocess，可插拔）  │
│  · 骨架/总结/问答 → LLM 适配器（OpenAI 兼容）│
│  · 术语表/标注/笔记 → SQLite               │
└───────────────┬──────────────────────────┘
                │ HTTPS（唯一出网）
     OpenAI 兼容 API（DeepSeek / GLM / 本地 ollama）
```

选型理由：

- **Python**：PDF 生态最全，且与 pdf2zh 同语言、可直接调度。
- **本地服务 + 浏览器 UI**：零打包负担即可用；需要分发时再套 Tauri。不上 Electron。
- **pdf2zh 仅 subprocess 调用**：引擎可插拔（预留接口换 BabelDOC/自研），与 AGPL 生态一致。
- **LLM 长上下文直塞**：单篇论文 <128K，不引入向量库——是减法不是偷懒。
- **成本**：一篇论文翻译+骨架+总结 ≈ 3 次长上下文调用，毛钱级。
- **版面升级路径**：PyMuPDF（MVP）→ MinerU/Docling（公式转 LaTeX，后置）。

## 7. 数据模型（草案，SQLite）

```
papers      (id, path, title, authors, doi, added_at)
paragraphs  (id, paper_id, page, bbox, text, order)
claims      (id, paper_id, text, anchor_paras)
annotations (id, para_id, role, evidence_text, confidence, source, user_override)
glossary    (id, term_en, term_zh, domain, note, source, hits)
qa_messages (id, paper_id, role, content, citations_json, created_at)
notes       (paper_id, markdown, updated_at)
```

## 8. MVP 范围与验收标准

**MVP = A1 + A2 + A3(手动术语表) + B1 + B2 + C1(一眼卡)**

验收（军令状，全部可测量）：

1. 拖入一篇真实双栏化学论文，3 分钟内看到排版完整的双语对照 PDF；
2. 骨架抽取以 10 篇自评：段落角色 ≥80% 正确，核心主张无遗漏；
3. 每个页边标签点击可跳转依据句；
4. 划词翻译对术语表内词条的命中率 ≥95%；
5. 全程零账号、零上传（LLM API 除外）；新机器 clone + 配 key 即可跑通。

**范围外**（防蔓延）：B3–B5、C2–C3、D 全部。

## 9. 里程碑

| 里程碑 | 内容 | 判定 |
|---|---|---|
| **M0 技术验证** | 无 UI：pdf2zh 跑通一篇真实论文；骨架链路（解析→LLM→结构化 JSON→人工看效果） | 效果肉眼可用 |
| **M1 MVP** | 阅读 UI + 术语表 + 骨架侧栏 | 达到上述 5 条验收 |
| **M2** | 三卡 + 问答 + 略读模式（C1、C2、B3） | 日常精读不再开其他工具 |
| **M3** | 术语本/笔记导出、多篇对比、Zotero 对接（D1–D3） | 读后沉淀闭环 |
| **M4+** | 审稿模式、MinerU 版面、OCR、Tauri 打包分发 | — |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 骨架判断错误 | 溯源 + 用户改判 + 中性措辞；学科 prompt 持续迭代 |
| pdf2zh 对个别版面失败 | 降级方案：段落级对照（PyMuPDF 对齐 + LLM 翻译） |
| AGPL 传染边界 | 全项目 AGPL-3.0；外部引擎一律 subprocess，不 import |
| LLM 服务商不可用/涨价 | OpenAI 兼容适配器可插拔，可换本地 ollama |
| 超长文献超上下文 | 骨架按节抽取再合并（天然可分节） |
| 术语表冷启动 | 内置化学/材料起步包（几十条高频术语），阅读中自动沉淀 |

## 11. 开源边界（永不混流）

- **入库**：代码、设计文档、内置术语起步包、测试样例 PDF（无版权问题者）。
- **不入库**：API key 与本地配置（`config*.yaml` 已 ignore）、个人术语表数据、个人文献库与笔记（`data/`、`library/`、`*.pdf` 已 ignore）。

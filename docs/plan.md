### T4 功能走查（每功能实测顺手度）

走查协议：每项功能按脚本操作，记录 完成秒数 / 卡点 / 情绪；卡点修复或砍功能，不修说明理由。

| 功能 | 任务脚本 | 通过线 |
|---|---|---|
| 导入 | 从 Zotero 拖一篇 PDF 进窗口 → 自动解析 | ≤20s 看到可读页面 |
| 析读 | 点析读 → 等待 → 骨架出现 | 等待有进度反馈，结果一眼能懂 |
| 精读 | 开略读扫核心段 → 关略读 → hover 任一标签 → 改判一个角色 | 改判立即生效并持久 |
| 眉批 | 生成眉批 → 点一条跳原文 → 看高亮定位 | 定位准确率抽查 ≥90% |
| 翻译 | 三模式各切一遍；划词翻译一个术语；收进术语表 | 全程无说明文字也能完成 |
| 问答 | 问固定 3 问 → 点引用跳转 | 引用跳转准确 |
| 删除 | 删一篇 → 文库与视图正确清空 | 无残留 |

**M2 出口验收**：三模式可用 + UI 无冗余文案 + 走查清单全过 + 截图存档 `_qa/shots/`。

## M3 · 沉淀与效率

1. 方法卡片（protocol 卡）：验收=一篇实验论文抽出可复现的材料/参数/步骤三段
2. 本文缩写表：骨架时顺带抽取；进术语 tab；可一键入术语表
3. 图表速览画廊：Figure 连图注；验收=图页论文不用读正文即可讲出主线
4. Markdown 导出：骨架+眉批+一眼卡+关键译文 → 单文件 .md；验收=导入 Obsidian 不乱
5. 术语导出 CSV/Anki

## 技术债与备忘

- LLM 输出归一化已做（键/枚举/范围校验），新功能沿用，禁止静默吞错
- 推理型模型（glm-5.3-flash）max_tokens 要留思考额度：骨架 16k、眉批 12k，新调用照此量级
- pdf2zh：google 在国内网络挂起（无快速失败），默认服务已是 bing；后续可给 subprocess 加首输出超时探测
- 骨架/眉批 prompt 的角色体系按化学定制；扩展学科时做成可配置模板而非硬编码
- 解析器对单栏/其他排版未系统验证，遇到再说（修复优先于预防）

### M3.4 补遗 · 「问/译」把手点不到（同日第二起）

用户报告：鼠标放到论文上会出现「问」「译」两个小字，移过去想点就消失。根因有三处叠加：

1. **2px 死区**：把手定位在纸缘外 2px，鼠标从正文出来穿过缝隙瞬间触发 `.page` 的 mouseleave，把手当场卸载——永远追不上。修复：把手加 16px 透明桥面搭在纸边上（`left: calc(100% - 16px); padding-left: 16px`），桥面是 `.page` 的后代区域，指针走桥面不触发 mouseleave。
2. **把手钉在段顶**：鼠标常悬在段落中部，按钮却在段落第一行的位置，斜着走很容易出界。修复：把手纵位跟鼠标（夹在段落带内），向右一小步就够到；另加 350ms 消失宽限，斜穿缝隙也不再半路蒸发。
3. **每页都长一个把手**：`v-if` 只判了 `hoverPara != null && it.text`，没判段落属不属于这页——悬停任何一段时 9 页页角各冒出一组野把手。修复：补 `paraByIdx[hoverPara]?.page === it.origPage`。

实测：悬停 → 水平直移（-14/-4/中心三点采样）→ 停留 400ms → 点击「问」，全程把手存在，右栏切到提问页并预填「¶1 这段在说什么？」；「译」走 mock 验证钉页边成功。测试中被 mock 覆盖的真实查译笔记（¶3）已用真实 API 重译恢复。

顺手根治了切换模式时偶发空白页：pdf.js 不允许并发 render 同一 canvas，快速连切三态时两个渲染任务会撞车。改为按画布把渲染任务串成队列链，轮到执行时重新对齐当前 scale/DOM，过期的排队任务直接作废。10 次连切回归：9/9 页渲染、零报错。

#### M3.5 补遗 · 改判回退与划词锚点（同日第三、四起）

排查上面那轮时顺手撞出来的两个真 bug：

1. **「回到推断」是坏的**。角色卡的下拉有「回到推断」（值 `""`），但后端 `override-role` 用 `role not in llm.ROLES` 校验，空串直接被判非法返回 400；前端又是内联 `await`，异常被静默吞掉——用户点了没反应，也不知道为什么。修复：后端空串 = 回到推断（`db.override_annotation` 本来就实现了这条分支，只是永远走不到）；前端把 `@override` 提成具名 handler，失败 toast 报出来。实测：改判 → 出现「已改判」小旗 + toast；回到推断 → 小旗消失、角色还原、toast「已回到推断」；非法角色仍被拒。
2. **划词定位不到段落时会把笔记钉到第一页**。`onMouseUp` 里 `paraIdx`/`page` 默认值是 `0`，段落命中失败就原样发出去，笔记于是落在 ¶0（第一页页边）上，而内容是别页的文字。修复：页码用选中文字所在页兜底，`para_idx` 记 −1（−1 是有效 int，能穿过 `int(body.get(...) or 0)`，且不会和任何真段落撞去重）。实测在第 3 页划词，payload 是 `{para: 9, page: 2}`。

另外把角色卡从「一滚就消失」改成**跟着书签走**：卡片位置每帧按书签的新矩形重算（rAF 节流），书签滚出书桌视野才自动收起。之前只要点击时浏览器为了把书签滚进视野而滚一下，滚事件就会立刻把卡片关掉（自动化里 100% 复现，人手速慢时也会遇到）。

### M3.6 · 交互手感（用户：要 macOS 那种灵动、流畅、不花哨）✅ 已完成（2026-09-11）

不是"多加点动画"，是先找出四类**跳变**，再逐条消掉。

| # | 问题 | 处理 |
|---|---|---|
| 1 | 所有浮层的**退场都是硬切**（只有入场动画：文库面板、设置弹窗、划词/框选气泡、角色卡、灯箱、快捷键卡、toast 全是 `v-if` 直接消失） | 全部改 `<Transition>`，统一 `pop`/`fade`/`slide-l` 三套；退场 120ms 短于入场 200ms |
| 2 | 换原文/译文/双语时**先闪一个"正在摆上书桌"加载器**，而且**读完的位置丢了**（切一下跳回第 1 页） | 换模式不再走加载器，改书桌顶部一条 2px 细进度线（不遮内容）；位置按「原文页码 + 页内比例」锚点落回 |
| 3 | 三个模式的**页号不是一回事**（原文 9 页 / 译文 9 页 / 双语 18 页，2i=原文 2i+1=译文），跳转和位置记忆会错位；更糟的是译文模式每页 `origPage=-1`，**`j/k` 步进、骨架跳转在译文模式下静默失效** | 加 `origPageOf()`/`pageItem()` 统一换算；`paraAbsY`/`applyJump` 都走它，译文模式下步进与跳转恢复 |
| 4 | 折叠右栏 / 缩放导致重排时**视线跳走** | 重排前记锚点、重排后落回；锚点只在一次 resize 连发的第一拍记录（右栏是 320ms 动画，中途每帧都重记会记到"新宽度+旧页高"的错位坐标） |

另外两处"花哨"：按钮 hover 的**悬浮上浮**（`translateY(-1px)` + 阴影）去掉，改成背景换色 + 按下压深；分段控件（原文/译文/双语）从"选中块瞬间变色"改成 **macOS 式滑块**——选中块自己滑过去，三个按钮强制等宽、滑块按 1/n 对齐（实测位移 0 / 47.99 / 95.98px，按钮均 48px）。缩略图 hover 从 3% 收到 2%。旁批被推开时改成 `transition: top 260ms` 滑过去而不是瞬移。

落位为什么要"量一次核对、偏了就再落一次"：它要跟换模式渲染、右栏宽度动画、画布重定标一堆异步赛跑，赌一次成功赌不赢。实测连续切 8 次模式，页码稳定停在原文第 1 页、页内比例 0.87→0.94（累计漂移 <0.07）。用户一旦自己滚动立刻停止追位。

**一条设计纪律（写进 visual.md）**：入场用 keyframes 而不是 transition——transition 的起点类要靠 `requestAnimationFrame` 摘掉，rAF 被节流时元素会卡在全透明；**内容绝不能挂在一个可能跑不动的过渡上**。这条是本次实测环境里发现的（本机 headless 浏览器动画时钟停摆，`getAnimations()[0].currentTime` 恒为 0），顺手把这条风险从设计里摘掉了。

### M3.7 · 色标重做：八色相 → 四档注意力（用户：彩色的图表太花哨）✅ 已完成（2026-09-11）

用户指着右栏"段落角色"那张图说太花哨。根因是**我自己违反了写进 visual.md 的纪律**——那条写着"八角色色只是调味，只以 ≤14px 书签片、3px 竖条出现，**永不作填充色**"，但角色书签和后来的图例色块恰恰是八个饱和色块平铺。

更根本的问题：**人能一眼解码的颜色上限是 3–4 个**。八个色相记不住，于是"对照参比 vs 优化拓展"这种细类其实没人能扫一眼认出来——颜色在制造噪音，不在传递信息。而"这段是全文的芯，还是铺垫"才是扫页边时真正要判断的。

改法：**色标只表达注意力**。一个暖色 + 三级灰，从深到浅就是"论证主干 → 外围让步 → 铺垫流程"：

| 档 | 填充 | 角色 |
|---|---|---|
| 核心主张 | `#D08A1C` 琥珀 | 全文的芯 |
| 论证主干 | `#57534A` 深灰 | 关键证据 · 缺口转折 |
| 外围与让步 | `#8E8A80` 中灰 | 对照参比 · 优化拓展 · 让步局限 |
| 铺垫与流程 | `#C9C4BA` 浅灰 | 背景铺垫 · 标准流程 |

眉批（原本九个色相）同样收敛成四档语义：值得读 / 要当心 / 是噪音 / 你自己钉的。

顺带：
- **图例即样本**——右栏那张表就是页边色块的样本（同色块、同字），两列素排、按注意力从深到浅排序（排序本身也是信息），去掉边框（边框会让 8 项看起来像 8 个按钮）。
- **文字色与填充色分家**：浅灰当文字在白底上看不见，所以另给一档正文可读的文字色阶梯（`ROLE_TEXT_COLOR` / `KIND_TEXT_COLOR`）。
- **对比度逐个核过**：四档色块字色 5.7 / 7.7 / 4.5 / 9.0，四档正文色 5.2 / 17.2 / 7.8 / 5.3，眉批标签 5.2 / 6.9 / 5.3 / 12.3——全部过 WCAG AA 4.5:1（原先八色相里有一半不达标）。

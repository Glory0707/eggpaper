### M3.4 补遗 · 「问/译」把手点不到（同日第二起）

用户报告：鼠标放到论文上会出现「问」「译」两个小字，移过去想点就消失。根因有三处叠加：

1. **2px 死区**：把手定位在纸缘外 2px，鼠标从正文出来穿过缝隙瞬间触发 `.page` 的 mouseleave，把手当场卸载——永远追不上。修复：把手加 16px 透明桥面搭在纸边上（`left: calc(100% - 16px); padding-left: 16px`），桥面是 `.page` 的后代区域，指针走桥面不触发 mouseleave。
2. **把手钉在段顶**：鼠标常悬在段落中部，按钮却在段落第一行的位置，斜着走很容易出界。修复：把手纵位跟鼠标（夹在段落带内），向右一小步就够到；另加 350ms 消失宽限，斜穿缝隙也不再半路蒸发。
3. **每页都长一个把手**：`v-if` 只判了 `hoverPara != null && it.text`，没判段落属不属于这页——悬停任何一段时 9 页页角各冒出一组野把手。修复：补 `paraByIdx[hoverPara]?.page === it.origPage`。

实测：悬停 → 水平直移（-14/-4/中心三点采样）→ 停留 400ms → 点击「问」，全程把手存在，右栏切到提问页并预填「¶1 这段在说什么？」；「译」走 mock 验证钉页边成功。测试中被 mock 覆盖的真实查译笔记（¶3）已用真实 API 重译恢复。

顺手根治了切换模式时偶发空白页：pdf.js 不允许并发 render 同一 canvas，快速连切三态时两个渲染任务会撞车。改为按画布把渲染任务串成队列链，轮到执行时重新对齐当前 scale/DOM，过期的排队任务直接作废。10 次连切回归：9/9 页渲染、零报错。

#### M3.5 补遗 · 改判回退与划词锚点（同日第三、四起）

排查上面那轮时顺手撞出来的两个真 bug：

1. **「回到推断」是坏的**。角色卡的下拉有「回到推断」（值 `""`），但后端 `override-role` 用 `role not in llm.ROLES` 校验，空串直接被判非法返回 400；前端又是内联 `await`，异常被静默吞掉——用户点了没反应，也不知道为什么。修复：后端空串 = 回到推断（`db.override_annotation` 本来就实现了这条分支，只是永远走不到）；前端把 `@override` 提成具名 handler，失败 toast 报出来。实测：改判 → 出现「已改判」小旗 + toast；回到推断 → 小旗消失、角色还原、toast「已回到推断」；非法角色仍被拒。
2. **划词定位不到段落时会把笔记钉到第一页**。`onMouseUp` 里 `paraIdx`/`page` 默认值是 `0`，段落命中失败就原样发出去，笔记于是落在 ¶0（第一页页边）上，而内容是别页的文字。修复：页码用选中文字所在页兜底，`para_idx` 记 −1（−1 是有效 int，能穿过 `int(body.get(...) or 0)`，且不会和任何真段落撞去重）。实测在第 3 页划词，payload 是 `{para: 9, page: 2}`。

另外把角色卡从「一滚就消失」改成**跟着书签走**：卡片位置每帧按书签的新矩形重算（rAF 节流），书签滚出书桌视野才自动收起。之前只要点击时浏览器为了把书签滚进视野而滚一下，滚事件就会立刻把卡片关掉（自动化里 100% 复现，人手速慢时也会遇到）。

### M3.9 · 纯白底 + 护眼底纹 + 拖拽浮层退不出去（用户三条）✅ 已完成（2026-09-11）

**① 拖拽浮层「进得来、出不去」**（用户："这个是什么时候触发的，我不小心触发了，还退不出去"）

浮层是拖 PDF 到窗口上时提示"松手，放到书桌上"。原来只挂了 `dragover` / `dragleave` 两个事件，三处边界全漏：

| 漏的地方 | 后果 |
|---|---|
| `@dragover.prevent` 无条件触发 | 拖**任何**东西都弹——拖选中的文字、拖页面里的图片也算 |
| `@drop.stop` 挂在书桌上 | 把 PDF 拖到论文上松手时，drop 根本冒不到 `.app`，那个负责 `dragOver=false` 的处理器永远不执行 → **浮层赖着不走**。更糟：drop 没被 `preventDefault`，浏览器会直接导航到那个 PDF，把整个应用冲掉 |
| 只在 `.app` 上听 `dragleave` | 松手落在窗口外、或窗口失焦时，事件不落到 `.app`，没人清 |

改法：拖入逻辑收成一个统一入口。只有 `dataTransfer.types` 含 `Files` 才算拖文件；`dragover` 仅在带文件时 `preventDefault`；`dragleave` 靠 `relatedTarget == null` 判断"真的离开窗口"（否则指针在论文上游走会被子元素的 dragleave 疯狂开关）；`dragend`、窗口 `blur`、`Esc` 都补上复位；书桌上的 `@drop.stop` 删掉，让 drop 冒到 `.app` 统一收。

实测六种边界（合成 DragEvent，Chromium）：

| 场景 | 期望 | 实测 |
|---|---|---|
| 拖文件进窗口 | 出现 | ✓ 出现 |
| 拖选中的文字 | 不出现 | ✓ 不出现 |
| 拖文件进来后松手落在窗口外 | 清掉 | ✓ 清掉 |
| 指针移出窗口（relatedTarget 为空） | 清掉 | ✓ 清掉 |
| 指针在论文上游走（子元素 dragleave） | 不被误清 | ✓ 保持 |
| Esc / 窗口失焦 | 清掉 | ✓ 清掉 |

drop 打在论文上：冒到 `.app`、浮层清掉、`defaultPrevented = true`（浏览器不再导航走）——这条同时修掉了一个隐藏的"拖一下整个应用就没了"。

**② 底色改纯白**

用户："整个背景不要现在的纸的颜色，就用纯白"。v3 的亮灰纸（#F4F2ED）连同桌面顶部那层暖色光晕一起去掉，四个 token 全白（桌面/面板/内容），沟槽留 `#F6F6F5` 一丝灰，否则页边批注带和桌面分不开。纯白底上论文页靠 `--shadow-page` 浮起来。略读蒙纱也从写死的暖纸色 `rgba(239,232,216,.9)` 改成 token `--veil`——白底上盖白纱才看得见（现在只有字淡下去，纸色不动，反而比原来那层米色带子干净）。

**③ 护眼底纹（设置里切，立刻生效，只存本机）**

用户："设置里面加一个护眼模式（你查一下护眼模式的颜色怎么调）"。查证结果：豆沙绿 `#C7EDCC`（199,237,204）是流传最广的经典值，另有浅青绿 `#CCE8E8`、米黄 `#F5F5DC`/`#FFF8DC`；这三个都源自 Office 2003 浅绿底（RGB 192,232,207）一脉的历史惯性，**ISO/IEC 9241、WHO、AAO 均未认证任何"护眼标准 RGB"**——有资料给出蓝光占比（豆沙绿 26%、纯白 33%）和 NASA-TLX 主观疲劳下降 31% 之类的数据，但都缺大样本临床验证；真正管用的是亮度、色温与看远处休息。所以做成四个可选项（纯白 / 豆沙绿 / 浅青绿 / 米黄），不是"药方"。

实现要点：**纸面上盖一层 `mix-blend-mode: multiply` 的色膜**，不是整屏蒙版也不是 `filter`。multiply 只乘"底"——白纸乘成护眼色，黑字乘完还是黑字。实测纸面 `#CDEFD1` 时正文仍有 **16.9:1** 对比度（纯白纸 21:1），一个字的清晰度都没让出去。桌面/面板换同色系浅底（桌面比纸面更浅，纸才浮得起来），`.page` 加 `isolation: isolate` 把洗色圈在纸内。

**根因一 · 竞态（真凶）**：`send()` 在 `convId` 还没载入时就把问题发了（服务端按"最近一摊"落库），紧接着 `loadConvs()` 把会话号补上 → 触发 `watch(convId)` → `loadMsgs()` 用数据库历史**整个替换** `msgs` → 用户气泡和在流式写入的助手气泡一起被换掉。回答继续往一个已经不在列表里的对象里吐，屏幕上什么都长不出来。
- 修：预填一律等首次载入（会话列表 + 历史）走完再落地（`ready` 闸门 + `pending` 暂存）；`loadMsgs()` 在 `busy` 时直接返回（屏幕上的 `msgs` 只能有一个作者：流式或历史）；`send()` 若发现没有会话号先取回来，别让服务端替我们猜是哪一摊；换会话先 `stop(true)` 再读历史。

**根因二 · abort**：AskPanel 挂在 `v-if="tab === 'ask'"` 上，切页签就 unmount → `onUnmounted → stop(true)` → 正在生成的回答被掐掉。"看一眼原文再回来"就永远等不到那句回答——DeepSeek/豆包都不会因为你切个标签页就取消回答。
- 修：提问面板改成**常驻**，`v-show` + 一层 `.ask-layer`（`.rbody` 加 `position: relative`，`.flush` 时 `inset:0` 正好铺满）。abort 从此只发生在关掉论文时，那才是真正"我不要这个回答了"的时刻。顺带补一句 `watch(tab)` → `askFocusTick++`，把"进页面就有光标"补回来。

**根因三 · 看起来像没反应**：思考型模型先想 30~60 秒才吐第一个字（实测首个字 53s、整段 66s），这段空窗期气泡里是全空的——**"正在想"和"发了没反应"在屏幕上长得一模一样**，用户据此判断"没有触发回答"完全合理。修：助手气泡在 `streaming && !content` 期间写「正在想…」（复用那三个点，顺手把 `.r-dots` 从 `.reading` 里提成全局工具类）。

**实测**：点「问 ↗」→ 2.5s 气泡写「正在想…」→ 53s 开始吐字 → 66s 完整回答，两行按序落库；中途切到术语页 2.5s 再切回，回答继续增长、请求无 abort；划词气泡的「提问」仍然只预填不自动发（输入框有字、无 `/ask` 请求）；进提问页自动聚焦输入框；四个页签逐个走一遍无 console 错误、面板贴合 rbody（`inset` 偏差 0/0/0/0）。我这轮测试留下的三条孤儿行（102/103/104）已删；用户自己那四条（96/98/99/101）没动——那是他们的数据，删不删由他们定。

### M3.24 · 打开论文的入场：破壳 → 纸面，以及换一句口号 ✅ 已完成（2026-09-12）

### M3.28 · 引用格式：拿得走的那一份 ✅ 已完成（2026-09-12）

用户："加论文引用格式功能（就是参考文献的那些引用格式），能直接复制，要包括各种类型（长的，短的，短的就是那种很短经常用在ppt里的那种），你先思考加在哪个位置，怎么个交互和展示再做。"

- 右栏四个页签（问题 / 速览 / 提问 / 术语）都属于"**读**"：引用格式不是读的时候要看的，读的时候你不需要参考文献条目。
- 它是"**把这篇带走**"的动作，而且是论文的**身份信息**（作者、刊名、卷期页、DOI）——跟顶栏那行标题是同一族数据。所以家安在**标题旁边**：一枚小 chip「引用」，点开一张浮层卡片。任何页签下都够得着，不占右栏版面，也不污染任何一栏的语义。
- 速览、文库都不放第二个入口（否则就是"同一批信息两处出现"，正是 M3.24 要清掉的那种重复）。

**格式分成三组**（长 / 短 / 导入，共九行）：

| 组 | 行 | 给谁用 |
|---|---|---|
| 参考文献条目 | GB/T 7714、APA 7、Nature 体 | 中文期刊与学位论文、英文期刊、理工投稿 |
| 短引用 | 作者 + 年、作者 + 期刊 + 年、正文括注 | PPT 角标与图注、PPT 页脚、写作时正文里引一句 |
| 导入与链接 | BibTeX、RIS、DOI（预印本则是 arXiv 编号） | LaTeX、Zotero/EndNote、投稿系统 |

**分工划在"谁做字符串"上**：模型只负责**从首页那几个印刷块里抄字段**（`llm.extract_citation`），排版一律由 `backend/citation.py` 用代码做。理由：让模型自己拼条目一定飘——多一个空格、少一个句点、页码该用连字符还是连接号，而引用格式恰恰是错一个字符就要返工的活。这也让格式可以脱网单测（`tools/citation_check.py` 手写元数据跑九种格式，改格式先跑它）。

**一个反直觉的地方**：引用信息藏的位置，恰好都是段落抽取**故意丢掉**的——页眉页脚的刊名卷期页（按 y 坐标裁掉了）、题目作者块（按机构关键词滤掉了）、DOI 行（跟在页脚里）。所以另写了一个 `pdfparse.citation_source()`：取首页原始行 + PDF 元数据，不筛选、不去重，连 arXiv 水印都不滤（那段"arXiv:2609.06350v1"正是预印本唯一的出处）。

**防编造守卫**（`citation.sanity()`，这次最要紧的一段）：参考文献里最不能容忍的错误是**看起来很像的假数据**——一个不存在的卷号、一段没印过的页码，会被原样抄进别人的论文，还没人会去核。所以除题目外，其余字段一律要求"这串字在首页文字里真的出现过"（归一化子串匹配，容忍跨行与各种横线：`6789␣–␣6795` 跨行也认）。题目允许回退到版面分析抽出的标题，作者一个都对不上就回退到抽出的第一作者，DOI 与 arXiv 编号在模型漏抄时再用正则补捞一次。

**实测**（库里那篇正好是 arXiv 预印本，是个好靶子）：`ZHOU S, LAVERNE J A, HLUSHKO H. Barrierless Water Dissociation…[EB/OL]. arXiv:2609.06350, 2026.` / APA 走到 `[Preprint]` + `https://doi.org/10.48550/arXiv.2609.06350`（arXiv 给每篇分配的那个 DOI，比自己拼 abs 链接稳）/ 短引用 `Zhou et al., arXiv, 2026`。识别耗时 2.4s，落库后 `cached=1` 秒回。字段核对行如实显示"期刊/卷/期/页码/DOI —"——预印本本来就没有这些，虚着比编一个强。

### M3.29 · 一轮打磨：旁批放开、勾划分笔、页边能自己写 ✅ 已完成（2026-09-12）

用户："把现在已经有的所有功能（比如旁批，骨架，提问等等）进行一轮优化打磨，扩展……表面的交互流畅性，动画的过渡流畅性，界面美观性，以及功能深层的内核性、实用性深化/扩展（比如旁批的种类和数量（可以自由一点）、勾划选中的内容的展示的美观性和精确度等等）"

**先审计，别凭印象改。** 拍了一轮现状截图 + 量了 DOM，量出三个真问题（另有一处看着像 bug 的灰块，`elementFromPoint` 一查是 pdf.js 还没画完的 canvas，不是我们的 UI——**没有量之前别急着改**）：

1. **划线的颜色根本没在工作**：所有类型都是 `KIND_COLOR + '2e'`（18% 浅色带）+ 每行一条下边线。噪音类是 `rgba(201,196,186,.18)`，在白纸上几乎不存在；要点类是一层灰蓝，像纸没擦干净。**颜色分了三档，笔触却只有一种**——信息全丢在同一个 alpha 里。
2. **同一行的高亮中间有洞**：归一化匹配只留字母数字，**空格被吃掉了**，而 pdf.js 把空格单独成节点 → 引文跨过空格时会得到两个矩形，实测留 8px 缝（nid 41：`x=491 w=150` 与 `x=649 w=169`）。
3. **术语表把术语切了**：`nowrap + ellipsis + max-width 38%`，于是 `adsorption ener…`、`coordination en…` 这种最该看全的长术语全被切掉——术语表的用处就是读全称，切了等于废掉一半。

**改了什么：**

- **旁批的种类放开**（内核性）：九种从"只能取这九种"变成"常用款"。装不下的东西模型可以自造：`kind=custom` + `label`（≤6 字，如"参考态不一""排版错位"）+ `band`（good/warn/noise）。band 只有一个作用——决定它在纸上怎么被划、页边什么颜色，所以**只有三档**：读者一眼分得清的也就是三档，再细分颜色等于没有颜色。解析时自造款要求"标签 + 档位"齐全才收，否则页面不知道把它画成什么。实测这篇论文模型自造了 3 条，全是九种装不下的真东西：「笔误」「参考态不一」「排版错位」。
- **数量放开**：每段 2 → 3 条，单批 10 → 16，总数 30 → 48（实测同一篇从 19 条变 23 条，一段顶到 3 条上限）。
- **读者也能写**（实用性扩展）：划词气泡多了「写批注」——`kind=note`、`band=mine`，页边显示「你 · 批注」，用墨色笔触。页边不只是"看 AI 说话的地方"，也是读者自己的本子。写进去的框**自动聚焦**（划完词接着就能打字，不用先点一下输入框）。
- **三档笔法**（美观性）：值得读 = 马克笔（有色带 + 实线脚）；要当心 = 波浪线（警示的通用形状）；可跳过 = 只有一条细点线（它本来就"可以跳过"，不该在纸上占视觉重量）；你自己的 = 墨色实线。`mix-blend-mode: multiply` 让色带压在字上时字**更实**而不是被洗白。hover 高亮从 `currentColor`（会丢掉类型色）改成加一圈墨环，颜色始终是这个批注的身份。
- **同行矩形合并**（精确度）：缝小于一个字高（0.9em）就接上，断在行之间不管（那是真的换行）。实测同一行相邻块的最小缝从 8px 变成 32px（真正的文字间距），无 5–20px 小缝。
- **引文能看全句**（实用性）：页边卡里的引文原来是 `nowrap + ellipsis`，40 字硬切。现在折行 + 明确的「全句」出口（展开后按钮变「收起」，卡高 100 → 161px 实测）。没有出口的截断才是问题，有出口的两行预览不是。
- **卡片加了色点和 `kindColor/kindZH/bandOf` 三个解析口**：原来"类型 → 颜色/标签"散在三个文件里，加一种类型要改五处。现在只有一处判断，自造款和用户批注都走它。
- **动效**：右栏三个静态页签加了过渡（出去 90ms、进来 170ms，合计 ~260ms——页签是高频动作，超过 300ms 就烦人）；六问的展开/收起改成 `grid-template-rows: 0fr→1fr` 真在动高度（实测逐帧 0→14→26→…→143px），不是"显示/隐藏"的跳变；方法卡「展开全部」后新露出的步骤一条条落下（6 步带错位延迟）。
- **术语页**：英文列允许折行（38% 定宽 + 截断 → 52% 自适应），中文去掉粗体让层次清楚，行距从 1.15 放到 1.5；缩写那一段反过来分宽度（左边是 RE/TPD 这种短记号，中文全称反而长）。实测 53 行**零截断**。

**顺手修掉两个硬伤**（都是这轮量出来的，不是新引入的）：

- `_resolve_rects` 拿 `search_for(quads=True)` 的结果当矩形取 `.x0`——Quad 只有四个角点，没有 x0。**只要页边出现一条没有矩形的钉子**（比如新写的用户批注），`GET /marginalia` 就整个 500，整页眉批打不开。改成不带 `quads=True`（返回的 Rect 才有 x0/y0/x1/y1）。

**测试纪律**：这轮**没有**跑"重新写眉批"来验证新提示词——`set_marginalia` 会整篇重写，而这篇页边上还有用户自己钉的查译，不能拿真实数据当靶子。改成在 `_qa/probe_marginalia.py` 里直接调 `llm.analyze_marginalia` 打分布（只读、不写库）；写批注那条路径则"建了再删"，收尾比对 id 集合确认零残留（`收尾后与动手前一致: True`）。验证自造类型的观感用 **DOM 注入**（往页边塞一张假卡截图，刷新即消失），数据库一个字节都不动。

### M4.4 · 双击打不开的真正原因（uvicorn 的日志配置）✅ 已完成（2026-09-12）

### M4.5 · 托盘图标与"点了没反应"：四个各自独立的 bug ✅ 已完成（2026-09-12）

### M4.7 · 图标：真凶是 index.html 里那条内联 SVG ✅ 已完成（2026-09-12）

用户："任务栏还是没变，任务栏你用桌面快捷方式图那个就行"

连着三轮我都在改 ICO 和几何，你每次都说"还是糊"。这轮的结论是：**前两轮改错了地方**。

- `backend/mark.py` **不再用手调的尺寸表**：缝 g 由"环内高度 / (2n+1)"解出来，放不下就**减字条**

  这个功能连糊三轮，根因就是判据只存在于我的感觉里。

manifest 同步换成这一整套；再加 `?v=` 版本号，因为**浏览器的图标缓存是按 URL 记的**：
URL 不变，它就一直给你旧图（这解释了"装完新版本图标一点变化都没有"）。

### M4.9 · 任务栏图标达到原生清晰度：进程外 WM_SETICON 注入 ✅ 已完成（2026-09-12）

用户："我要特别清晰那种，非常非常清晰的矢量图那种"，并授权我自己上机、自己点安装包，一直弄到好。

先说为什么前面几轮没到头：favicon 这条路**注定软**。三组实验把它钉死了——

1. **彩色指纹 ICO**（每个尺寸染一个纯色，看任务栏取哪档）：150% 缩放下 Chromium 按**物理像素**
   取 24px 那一档，却被 Windows 当逻辑 24 再放大到 36/48 物理像素。源头位图偏小，画得再好也白搭。
2. **满幅红方块标定**：注入 48/32/24 的满幅 HICON，任务栏都显示成 **48×48 物理像素**的槽位——
   槽位是 48，而它拿到的源图是 24，所以软。
3. **`--app-icon=...ico` 开关**：红方块 A/B，任务栏零变化，此开关对应用模式窗口无效。

**解法（`backend/window.py` `_give_window_icon`）**：浏览器是我们自己用 `subprocess` 拉起来的，
窗口出现后，从进程外用原生 API 把图标盖掉——

- 按标题 + PID 找到那个 `Chrome_WidgetWin_1` 窗口；
- `GetDpiForWindow` 问窗口真实 DPI，`GetSystemMetricsForDpi` 问出大/小图标的**物理像素**
  （这台 150%：大 48、小 24）；
- 不再用 `LoadImage` 从 ICO 选档（实测它会挑 60 再缩回 48，仍有一次重采样），而是
  `mark.draw(48)` **按精确像素现画**，`CreateBitmap` + `CreateIconIndirect` 直接造 HICON；
- `WM_SETICON` 三个槽都盖。**分色实验测出 Windows 11 任务栏读的是 `ICON_SMALL2`**
  （BIG 放红、SMALL 放绿、SMALL2 放蓝，任务栏显蓝），所以把 48 的大图放进 SMALL2，1:1 落槽。
- Chromium 在 favicon 加载后会把图标重设回去，注入在后台线程里**反复压约 30 秒**。
  本地是单页应用，之后不导航，图标稳定。

**顺带修掉图标边缘一圈灰边**：超采样缩小时，透明像素 RGB 是 (0,0,0)，LANCZOS 在圆角处把白和
"透明黑"平均，白块外缘发灰（`mark._downscale_pm`：先预乘 alpha 再缩，整数倍用 BOX 无振铃，
缩完还原）。ICO 也补齐了每档 DPI 的精确尺寸（30/36/42/60/72），并统一白底。

**验证**：冻结版安装后 `/api/window` 开窗口，任务栏按钮 = 48 物理像素 1:1、四根字条、白缝分明、
圆角无灰边，与桌面快捷方式（同一份 mark.draw(48) 位图）同级；源码/冻结两路径日志都写
"窗口图标已按物理像素注入"。标题栏用 SMALL=24 的现画图。

**方法沉淀**：小图标的"糊"要靠实验定位，不能靠眼睛猜——彩色指纹回答"它取哪一档"，
满幅色块回答"槽位到底多大、有没有 1:1"，分色回答"系统读哪个图标槽"。

### M4.17 · 整本翻译：那个终端是哪来的 + 为什么它永远不动 ✅ 已完成（2026-09-12）

用户："现在的整本翻译会不会太慢了，为什么点整本翻译启动了一个终端"

两个问题，第一个不是"慢"，是**永远不动**：

- **终端**：`pdf2zh.exe` 是控制台程序，而打包版 eggpaper 自己没有控制台
  （console=False）。Windows 的规矩是——没有控制台的进程起控制台子进程，就给它新开一个窗口。
  抓到的现场是：子进程 python.exe 底下挂了 conhost.exe，屏幕上多出一个 **Windows Terminal
  窗口**（窗口类 `CASCADIA_HOSTING_WINDOW_CLASS`，标题就是 pdf2zh 的 exe 全路径）。
  它不是我打印的日志窗口，是 pdf2zh 自己的控制台。修法：`CREATE_NO_WINDOW` + `SW_HIDE`。
- **不动**：默认服务配的是 `google`（translate.google.com）。这台机器上**连不通**，
  而 pdf2zh 对连不通的服务不是报错而是死等重试——实测进程 CPU 恒为 0、4 分钟 0 输出、
  界面永远停在「翻译中」。修法：开跑前先 TCP 预检（2.5 秒，结果缓存 10 分钟），
  不通就自动换 bing 并把"换过了"说出来；都不通就当场报错，一句话说清怎么办。
  默认服务也从 `google` 改成 `bing`。

顺带修掉三个一起埋着的雷：

1. **完成通知整条是死的**。前端判断"是否在译"看的是数据库里的 `translate_status`，
   而这一列**从来没被写成 running**（只有 done 那一处写入）。于是「翻译中…」永远不会出现、
   完成提示永远不弹、`译文/双语` 两个按钮译完了也点不动。现在开始就写 running，
   失败写 error，状态查询顺手把 done/error 同步回库。
2. **产物会串篇**。整个翻译件共用一个 out_dir，pdf2zh 按输入名命名产物
   （`<pid>.pdf` → `<pid>-dual.pdf`），而老代码是 `sorted(os.listdir())[0]` ——
   译第二篇时会把第一篇的双语 PDF 认成自己的（A 的译文挂到 B 上）。现在按源文件名找。
3. `extra` 参数在 `_cmd` 和调用处各拼了一次，配了 options 就会传两遍。

另外加了：pdf2zh 的 stdout 逐行读（tqdm 的 `k/N` 抠出来当页进度，其余写 app.log）、
卡死看门狗（6 分钟无输出就杀，报"卡住了"而不是永远转）、孤儿译文认领
（eggpaper 关掉时 pdf2zh 还在跑，它会把译完的文件写完；启动时看到完整产物直接认领成 done，
不再白译一场）、设置里的服务选项改成说人话（并注明 google 多数网络连不通）。

**实测**（18 页 / 7.1 MB 的真论文）：

- 冷跑 `--service bing` 一遍：**121 s**（页进度 ~4–6 s/页），产物 dual+mono 都在。
  所以这不是"慢"，是"卡"。第二次起命中 pdf2zh 的段落缓存，同一篇只要 15 s。
- 控制台窗口 A/B（`_qa/test_translate_nowindow.py`，GUI 爹 pythonw → 控制台孩子，
  数屏幕上**看得见的**窗口）：不带旗标新增 2 个（含那个 Windows Terminal 窗口），带旗标 0 个。
  注意：数 conhost **进程**是测不出结论的（带旗标照样有 conhost，只是不显示窗口）；
  拿 bash/cmd 当爹也复现不出来（它们自己有控制台，子进程是继承的）。
- 端到端（`_qa/test_translate_e2e.py`，真 HTTP + 真 pdf2zh）：配置写 google →
  返回 `{"service":"bing","note":"google 在你的网络下不通……已自动改用 bing"}`；
  数据库进 running；进度 `[2,18] → [9,18] → [18,18]`；结束落库 dual/mono、
  `/pdf?variant=dual` 取得到 PDF；失败路径（服务名 pdf2zh 不认）报人话且落 error。
- 界面（`_qa/test_translate_ui.py`，真 Edge）：按钮变 `翻译中 5/18`、工具栏下沿出现发丝进度条
  且宽度与页数一致（28% = 5/18）、译完弹「双语已生成」、进度条消失、`译文/双语` 解禁、
  切到双语的画面正常（左右两页，奇原文偶译文）。

补充两处（同一轮里发现的）：

- **key 不许被复制到 pdf2zh 自己的配置里**。pdf2zh 的 `set_envs()` 会把从环境变量读到的
  `OPENAI_API_KEY` / `DEEPSEEK_API_KEY` **写进 `~/.config/PDFMathTranslate/config.json`**
  （它自己的 GUI 靠那个文件）。用户只是在 eggpaper 里选了个服务，key 不该顺带被复制到
  另一个程序的配置里。现在传 `--config <副本>`（副本先原样装真配置的内容，行为不变），
  用完删掉，启动时也扫一次残留。实测（假 key）：真配置的 mtime 与 sha256 一个字节没动。
- **key 错了要当场说**。实测假 key 时 pdf2zh **不会中止**：它逐段刷 `401` 一路把所有页
  都试完（5 分钟以上），输出一直在动所以卡死看门狗也不响。现在认出鉴权失败就立即掐掉并报
  "key 不对"（实测 8 秒）。

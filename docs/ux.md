# eggpaper 交互设计（UX）

> v0.1 · 2026-09-11。上位文档：[design.md](design.md) v0.2。本文回答四件事：页面怎么排、交互逻辑是什么、依据什么人因模型、哪些新功能配得上进界面。

---

## 1. 人因模型：人到底怎么读文献

| 真实行为 | 对工具的要求 |
|---|---|
| **非线性**：标题→摘要→图→缺口句→主结果→结论，几乎没人从头读到尾 | 导航按"论证结构"组织，不按页码组织 |
| **锚点+短途迁移**：盯着一个句子，查缩写/看引用/跳图表，然后回到原位 | 每次迁出必须便宜，**回来必须自动**——丢位置是最大隐性成本 |
| **双任务阅读**：读英文+核对中文同时进行 | 译文位置必须空间可预测（永远在同样的相对位置），让眼睛形成肌肉记忆 |
| **双姿态**：速览（2-10 分钟筛选）与精读（30-90 分钟）注意力模式完全不同 | 界面有两种"姿势"，且姿势跟随任务自动切换，不让用户配 |
| **积累感**：读过的论文是"我的副本"——划线、批注、查过的词 | 页边是读者资产，随阅读增值，可整体带走（导出） |

由此推出评估任何交互的三问：**迁出便宜吗？回来自动吗？沉淀下来了吗？**

## 2. 现有界面自省（五宗罪）

1. **左栏文库是阅读时的死重**——导入一次后 248px 纯占地，挤占最贵的阅读宽度。
2. **右栏四个 tab 平行摆放**——但阅读流程是串行的：速览(读前)→骨架(一次性)→提问(偶发)→术语(低频)。容器不跟随任务。
3. **查译用完即丢**——划词气泡关掉就没了。读者查过的词本该留在页边成为自己的批注。
4. **零键盘流**——j/k 翻段、t 译段这类高频操作全靠鼠标往返，是最大的隐形负担。
5. **跳转有去无回**——点引用/主张跳走之后，回不来。

## 3. 页面布局：书桌三态（另有宽窄两套排布，见 visual.md §6）

布局不做"三种模式"的显式开关——**姿势跟随任务自动切换**（选了什么任务，界面就摆成什么样子）。

### 3.1 阅读态（默认：原文精读）

```
┌────────────────────────────────────────────────────────────────┐
│ 🥚  [论文标题………………………………]  9页·23段   原文│译文│双语  ◻略读  析读 ⚙ │
├──┬──────────────────────────────────────────────┬──────────────┤
│▮ │   ┌────────────────┐   [¶页边批注带]          │  右栏四个页签  │
│文│   │   原文 page 3   │  ▍点睛之笔 两条路径…     │ 问题 / 速览 /  │
│库│   │                │  ▍有坑 0.1eV误差…       │ 提问 / 术语    │
叠│   │                │                        │ 读至 ¶13 / 23 │
│44│   └────────────────┘                        ├──────────────┤
│px│                                             │速览│提问│术语 │
└──┴──────────────────────────────────────────────┴──────────────┘
```

- **左栏收纳成 44px 图标条**：文库入口+篇数角标；点开为浮出面板，选中后自动收回。阅读宽度还给正文。
- **右栏可折叠**：边缘 chevron / 快捷键 x；折叠状态记忆。默认宽度 300→288。
- **顶栏只留高频控件**：三态翻译 segmented + 略读 + 析读 + ⚙。骨架/眉批图层开关收进 ⚙（默认开，极少动）。

### 3.2 校对态（双语·对开）

选「双语+对开」自动进入：**右栏自动收起、页边批注带自动隐藏**，屏宽全给左右两页；

```
│   ┌─────────────┬─────────────┐   │
│   │ 原文 page 3  │ 译文 page 3  │   │  ← 左右同高对齐，横向视线往返最短
│   └─────────────┴─────────────┘   │
│   ┌─────────────┬─────────────┐   │
│   │ 原文 page 4  │ 译文 page 4  │   │
```

窄窗口（<1180px）对开自动退回交替单页，不做提示文案（行为即说明）。

### 3.3 速览态（读前筛选）

点右栏「速览」tab 即进入：一眼卡置顶（一句话 + 发现），下面依次是图表、方法卡、导师三问；此时若切到「译文」整版模式即成"中文快读"。无需独立开关。

**速览页只负责三件事**：三十秒定位（一眼卡）、能不能复现（方法卡）、组会会被问什么（导师三问）。"为什么重要"归问题页②、"依据在哪"归③、"作者承认了什么"归④——一眼卡那两行只写结论 + 一个 ↗ 指针，点它跳到对应那一问，**不在两个页签里各说一遍**。

## 3.4 信息归属：每条信息只有一个家

这是这个界面最重要的一条约束，比任何一条视觉规范都硬。右栏四个页签 + 纸面 + 浮层，看起来是六个地方，
其实是六个**房间**：一条信息住一间，别处只能挂门牌。

| 信息 | 唯一的家 | 别处只能这样出现 |
|---|---|---|
| 原文 / 译文 | 纸面 | — |
| 眉批（9 类常用款 + 自造款 + 你自己写的）与引文划线 | 纸面页边，钉在它引的那句话旁 | 问题④引用其中「有坑」的那几条（回答"还有什么没解决"必须举得出来）；右栏没有第二份列表 |
| 段落角色（8 类） | 后台数据，只驱动**略读**（决定哪几段变灰） | 问题③的证据行以"关键证据 / 对照参比"出现一次 |
| 段落 purpose（作者写这段干嘛） | 问题③④的证据行 | — |
| 这篇讲什么 | 速览·一眼卡（一句话） | 问题①—④是逐条追问版；一眼卡不复制，只给 ↗ |
| 为什么重要 | 问题② | 一眼卡不重复（原「贡献」行已删） |
| 结论里的数字 | 速览一眼卡的「发现」＋问题③的主张链（前者一句、后者带 ¶） | — |
| 作者承认的局限 + 可疑之处 | 问题④ | —（速览一眼卡曾有「待解」计数行，已删——那一行的活儿本来就在④） |
| 顺着往下能做什么 | 问题⑤ | 导师三问不复述（提示词里划死边界） |
| 答辩会被问什么 | 速览·导师三问 | — |
| 换个学科怎么看 | 问题⑥ | — |
| 能不能复现（方法） | 速览·方法卡 | 问题③末尾给一个「方法卡 ↗」入口 |
| 图 | 速览·图表速览（缩略图 + 灯箱） | 纸面正文里当然还有原图（那是原文） |
| 术语 / 缩写 | 术语页 | 划词气泡命中术语时给一枚 chip（读的时候要看得见） |
| 问答 | 提问页 | 划词 / 眉批 / 六问上的 ↗ 只把问题送进去 |
| 阅读进度 | 纸面右缘那根线 + 问题页「读至 ¶n / N」 | — |
| 引用格式（参考文献 / 短引用 / 导入） | 顶栏标题旁的「引用」浮层 | 别处不放第二份（速览、问题、文库都没有引用入口）——它跟标题同族，都是"这篇是谁"，所以家在标题旁边；任何页签下都够得着 |

**四条推论**（新加 UI 之前先过一遍）：

1. **一个判断只在一个地方展开，别处只给指针或计数。** 一眼卡「发现」右侧的 ↗ 就是这条的形状：发现 → ③。（「待解」计数行已删：它是④的预告，读者真要看得自己翻开④——一句话能说完的才配留在一眼卡上。）
2. **派生视图不许复制内容。** "同一批文字的第二种排法"不是第二种信息（眉批速览、依据 ¶n 行、段落角色汇总都是这么死的）。
3. **跨模块去重靠信息分工，不靠提示词里写"别重复"。** 两条生成链路互不知情、素材又同源（都是主张 + 眉批有坑），所以边界要写进各自的提示词：④＝作者承认的、⑤＝顺着往下做的、导师三问＝在这之上再狠一层。
4. **算过的进页面就显示（读缓存不花钱），没算过的绝不偷偷算。** `?cached=1` 是这条的实现：进页面静默读一次，没有就给一个小「获取」——一次模型调用永远是一次用户授权。

新加一块东西之前，先在这张表里问一句：这条信息有家了吗？**有，就只能加指针；没有，它才是新的一块。**

## 4. 交互逻辑七原则

1. **位置即状态**：重开论文恢复上次滚动位置+模式+图层；任何跳转入栈，`Alt+←` 或页角"返回"chip 回到迁出点。
2. **动作不打断视线**：段落级操作不额外挂浮件——划选即出气泡（翻译 / 钉页边 / 收进术语 / 提问），键盘 `t` 直接译当前段。早先版本在页边挂了 hover 把手（译此段 / 问这段），与划词重复且老是追不上鼠标，已删。
3. **批注即沉淀**：页边承载两种声音——AI 眉批（推断）+ 你的查译/问句（资产）。划词译文一键"钉在页边"，关掉气泡也不丢；这就是"你的批注本"，导出=带走副本。
4. **姿势跟随任务**：见三态；不给用户"模式设置"，只给任务入口。
5. **键盘全达，鼠标不强制**：见第 6 节地图。
6. **可发现性分级**：默认界面 ≤6 个控件；低频操作收进 ⚙/hover；不加解释文案，行为即说明。
7. **反馈可撤销**：角色改判立即生效并显示"已改"角标，可一键回退到推断值。

## 5. 交互清单（控件 → 触发 → 反馈 → 撤销）

| 交互 | 触发 | 反馈 | 撤销/返回 |
|---|---|---|---|
| 查词并钉页边 | 划词→气泡「钉在页边」 | 查译卡入页边，与眉批同列但标注"你" | 卡上 × 移除 |
| 译此段 | 按 `t`（译当前阅读段） | 译文卡钉在该段页边 | 卡上 × |
| 问这段 | 划词→气泡「提问」 | 右栏提问抽屉滑出，问题自动带段落引用 | Alt+← 回原位 |
| 骨架跳转 | 点树节点/图例 | 滚动+琥珀闪烁 | Alt+← |
| 引用跳转 | 点答案内 ¶n | 滚动+闪烁 | Alt+← |
| 略读 | f 或顶栏 | 背景/样板/参考文献整段变灰（含符号），图注/首页/有批注的段不灰；j/k 只在核心段间跳；悬停灰字回黑，点一下=这段也要读 | 再按 f |
| 三态翻译 | 1/2/3 或 segmented | 姿势自动切换（3.2/3.3） | — |
| 文库 | 左条图标或 g l | 浮出面板 | 选中自动收 / Esc |
| 护眼底纹 | 设置里点一下色片 | 整窗换色（桌面/面板/纸面一起） | 点「纯白」 |
| 翻页 | `PageUp` / `PageDown`、控件条 ‹ ›、页码直达 | 滚到该页首，即时（不平滑滚动等动画） | 回到原页 / Alt+← |
| 缩放 | 控件条「适宽 / 适页 / 百分比 / －＋」、**Ctrl+滚轮** | 只重排论文，顶栏右栏一律不动；光标底下那个字留在原地不跑 | 点「适宽」 |
| 论文内查找 | `Ctrl+F` 或控件条「查找」 | 命中逐处高亮（精确到字符），计数 n/N，逐个跳转 | Esc / × |
| 图表翻页 | 灯箱里 ‹ › 或 ←/→ | 上/下一张图，计数跟着变 | Esc / 点外部 |
| 拖动浮窗 | 按住浮窗（或其标题行）拖 | 跟手移动；拖过就不算点击，不会顺手关掉 | 拖回 / 关掉重开 |
| **拖栏宽** | 拖右栏/文库的内侧边缘；`←`/`→`（先 Tab 到拖手）；双击复位 | 只动栏宽，论文**松手后**才重新定标并落回原来那一行 | 双击回默认宽 |
| **推荐问题** | 提问页空态 | 竖排四问，**整句显示不截断**（七八十字符的问题要能读完）；未生成时先给四条通用问题顶上 | 点任一条直接发出去 |
| **提问（对话）** | 右栏「提问」，Enter 发送 | 回答逐字出现，句尾 ¶ 号可点回原文；每条消息悬停出「复制 / 重新生成 / 删除」；**等第一个字时写「正在想…」**；**切页签不打断生成**（面板常驻，回来接着看） | 「停止生成」留住半截；「重新生成」撤掉这一问一答重问 |
| **从别处问过来** | 眉批 / 证据行 / 六问⑤⑥ 上的「问 ↗」「追问 ↗」 | 直接切到提问页并**问出去**，不用再按一次回车；划词气泡的「提问」只预填、等你改完再发 | 在输入框里改完再 Enter；或点「停止生成」 |
| **新对话 / 切换对话** | 会话下拉切换，「＋」新开一摊 | 上下文按会话隔离；标题取第一个问题；**名字后面不带问答条数**（"· 4"只会把名字挤短），**没问过话的空会话不列进来**（点几下 ＋ 攒出的同名"新对话"是噪音，当前这一摊永远留着） | 会话栏最右那个删除键删掉整摊（含里面的问答） |
| **文库分类** | 左栏文库 →「＋ 新建分类」；条目右上角数字打开勾选；也可把条目**拖到**左侧分类上 | 一篇可同时属于多个分类；点分类即筛选，再配合搜索与排序 | 分类上 × 删分类（文献不动）；条目上取消勾选 |
| **阅读进度** | 滚动 | 书桌右缘一根细线随阅读长高（读到哪里一眼可见，不写字） | — |
| **划词气泡** | 划选文本 | 气泡出现：已选字符数 + 翻译 / 钉页边 / 收进术语 / 提问 | **点它以外任何地方都收**（含纸面本身）、Esc、右上角 × |
| **本文缩写** | 术语页顶部 | 只列**还没收进术语表**的缩写，右边一个 ＋ | 点 ＋ 收进术语表（它就从上面消失、出现在下面的表里） |
| **文库条目** | 看列表 | 一行只有：`＋`（归入分类）、标题、第一作者 | 点 `＋` 勾选 / 直接把条目拖到左侧分类 |
| **问题** | 右栏第一个页签 | 六行问题排在那里，收起时右侧一个读数（1 / 5 / 6）；点哪条摊开哪条 | 再点收起；换篇回到"只有问题" |
| **速览** | 右栏第二个页签 | 一眼卡（一句话 + 发现，「发现」带 ↗ 指向问题③）→ 图表 → 方法卡（默认三行 + 前三步，「展开全部」）→ 导师三问 → 导出；算过的块**进页面就显示**（读缓存不花钱），没算过才给一个小「获取」 | 点 ↗ 跳去对应的问题；「展开全部」看余下步骤 |
| **眉批** | 纸面页边（唯一内容）· 问题页只给生成入口 | 每条批注钉在它引的那句话旁，标签（九种常用款 + 模型自造款 + 「你 ·」你自己写的）+ 色点 + 引文 + 展开/移除；纸上按档位分三种笔触（值得读是马克笔、要当心是波浪线、可跳过只有点线）；「有坑」那类在问题④里被引用一次 | 点卡展开/收起；悬停右上角 ×；「问 ↗」就这条追问；引文「全句」摊开整句 |
| **还能做什么 / 换个学科** | 点「获取」 | 生成 2~3 条，每条带一句「追问 ↗」 | 点「追问」带进提问面板直接问出去 |
| **确认与输入** | 删会话 / 删分类 / 删文献 / 改会话名 | **应用内对话框**（不是系统弹窗）：标题 + 一句后果说明 + 取消/确定，危险动作的确定键是朱红；可拖走；Esc 与点遮罩取消，Enter 确定 | 取消 |
| **① 要解决什么** | 展开第一问 | **模型直接说清的一句话**（一到两句 + 句尾 [¶n] 可点）——原文里没有哪一句现成写着"我们要解决什么"，那是要从引言里综合出来的，所以这一问不给原文摘句 | 点句尾的 ¶ 跳到纸面 |
| **④ 还有什么没解决** | 展开第四问 | 目的句 + **作者自己承认时的那句话**（断在句末，点了跳纸面）+ 眉批标出的「有坑」 | 点摘句跳到纸上那句话 |
| **字号** | 设置 →「字号」 | 小 / 标准 / 大 / 特大，点一下立刻生效（看得到效果才知道合不合适，所以不进「保存」）；**论文正文不受影响** | 点回「标准」 |
| **引用格式** | 顶栏标题旁的「引用」（任何页签下都在） | 浮层里三组：参考文献条目（GB/T 7714 / APA 7 / Nature 体）· 短引用（作者+年 / 作者+期刊+年 / 正文括注，PPT 与图注用）· 导入（BibTeX / RIS / DOI 或 arXiv 编号）。**点整行即复制**，标注 toast「已复制 · GB/T 7714」；顶部一行字段核对（没认出来的字段虚着显示 `—`）。识别只做一次（一次模型调用），之后排版全在本地；条目一律整条换行显示，不截断 | Esc / 点遮罩关闭；认错了点「重新识别」；「去核对 ↗」开 DOI 或 arXiv 页 |
| **自己写一条批注** | 划词 → 气泡「写批注」 | 气泡里长出一块写字的地方（**自动聚焦**，划完词接着打字），Ctrl+Enter 或「写到页边」保存；页边显示「你 · 批注」，用墨色笔触，和你钉的查译同一种气质 | 「取消」丢弃草稿；页边上悬停出 × 移除 |
| **批注类型** | 页边卡片的标签（九种常用款 + 模型自造款） | 颜色只有三档（值得读 / 要当心 / 可跳过），自造款带自己的短标签（"参考态不一""排版错位"）——**档位决定笔触，标签决定名字**，读者要认的只有三档 | 标签前的色点 + 纸上对应的笔触一起指认 |
| **引文看全句** | 页边卡里的引文（默认一行，切口带省略号） | 点「全句」在卡里摊开整句（最多 108px 高，超出在自己内部滚）；引文本身点了是**跳回纸上那句话**——两个动作分开，不挤在一个点击上 | 再点「收起」 |

## 6. 键盘地图（默认隐藏，按 ? 显示半透明卡片）

| **多会话流式提问**（停止/复制/重生成/逐条删除） | 提问是这个工具里唯一"对话"的场景，等待和多摊话题都要被照顾到 | 中（SSE + 会话表） | M3.12 |
| **文库分类 + 搜索 + 排序** | 一次读的文献很快就不止几篇，"最近读过哪篇"是最常问的问题 | 中 | M3.12 |
| **栏宽可拖 + 页边按需给宽** | 论文的宽度不该被两个固定栏决定 | 低 | M3.12 |

| **会话上下文压缩**（超限折成摘要而不是截断） | 长会话里，用户早先确认过的结论不能凭空消失 | 中（多一次模型调用/每次折叠） | M3.13 |

**明确不做**：多论文并读（窗口分裂，违背单锚点深读）· 深色模式（反色会让 PDF 图表失真、也砸掉"纸"的隐喻；护眼需求的正解是**护眼底纹**——把纸面染柔而不是翻黑，已实现）· 段内术语悬停提示（textLayer 标注成本高收益低）· **缩论文正文的字号**（PDF 版面固定，缩字会让图表和行内标注一起错位；界面字号可调——见设置里的「字号」，论文例外）· 分类层级树与保存的检索式（Zotero 那套在几十篇的体量下是负担，扁平分类 + 搜索足够）· 标签（标签和分类在这里表达的是同一件事，只保留一种）。

## 1. 人因模型：人到底怎么读文献

| 真实行为 | 对工具的要求 |
|---|---|
| **非线性**：标题→摘要→图→缺口句→主结果→结论，几乎没人从头读到尾 | 导航按"论证结构"组织，不按页码组织 |
| **锚点+短途迁移**：盯着一个句子，查缩写/看引用/跳图表，然后回到原位 | 每次迁出必须便宜，**回来必须自动**——丢位置是最大隐性成本 |
| **双任务阅读**：读英文+核对中文同时进行 | 译文位置必须空间可预测（永远在同样的相对位置），让眼睛形成肌肉记忆 |
| **双姿态**：速览（2-10 分钟筛选）与精读（30-90 分钟）注意力模式完全不同 | 界面有两种"姿势"，姿势跟随任务自动切换，不让用户配 |
| **积累感**：读过的论文是"我的副本"——划线、批注、查过的词 | 页边是读者资产，随阅读增值，可整体带走（导出） |

由此推出评估任何交互的三问：**迁出便宜吗？回来自动吗？沉淀下来了吗？**

## 2. 书桌布局：姿势跟随任务

布局不做"三种模式"的显式开关——**姿势跟随任务自动切换**（选了什么任务，界面就摆成什么样子）。

- **阅读态（默认）**：左栏文库 + 纸面 + 右栏（问题/速览/提问/术语）。右栏可折叠（`x`、边缘 chevron，状态记忆）；顶栏只留高频控件（三态翻译 + 析读 + ⚙，眉批图层开关收进 ⚙）。
- **校对态（双语·对开）**：选「双语+对开」自动进入——右栏自动收起、页边批注带自动隐藏，屏宽全给左右两页，左右同高对齐（横向视线往返最短）。窄窗（<1180px）对开自动退回交替单页，不做提示文案（行为即说明）。
- **速览态（读前筛选）**：点右栏「速览」即进入：一眼卡置顶，下面依次图表、方法卡/谱系卡、导师三问；此时切「译文」整版即成中文快读。速览只负责三件事——三十秒定位（一眼卡）、能不能复现（方法卡）、组会会被问什么（导师三问）。

**宽窄两套排布**：宽窗（≥1180px）三段式，右栏是版面的一部分；窄窗（<1180px）右栏改成**浮在书桌上的抽屉**（`position: fixed`，只留一道投影），跨进窄窗时自动收起一次（只在跨门槛那一拍动手，用户手动再开就不干预）；再窄（<1000px）让出顶栏的论文标题——纸面上本来就写着它。336px 的固定栏在 1100px 窗口里会吃掉三分之一，论文被压到 452px 宽（实测），根本读不了。

**栏宽可以拖（右栏、文库两处同一套手势）**：按住栏边拖动改宽度，双击复位，方向键也能调（±28px）。右栏 268–760px（默认 336），文库 236–560px，宽度写进 localStorage。

- 拖手贴在面板**内侧边缘**（9px 无形条，hover 显出 2px 强调色线）——放内侧是因为 `.rail-wrap` 有 `overflow: hidden`（收起时裁内容），伸到外面的手会被一起裁掉。
- **拖的过程中不重新给论文定标**：栏宽一变 fitScale 就得重算、九页画布全要重画，每帧都做就是卡手。拖动期间只动栏边（关掉宽度过渡），**松手才重排一次**，并按锚点落回原来那一行。
- 窄窗里右栏宽度取 `min(栏宽, 92vw)`——拖到头也只是"占满"，不会把左半边推到屏幕外。

**两个布局实现的坑**：

- **居中不能用 flex 的 `align-items: center`**：内容比容器宽时（放大论文），flex 居中会把左半边推到滚动区之外，左边那截再也滚不回来（实测 205% 时论文左边缘在 −161px，横向可滚 207px 全在右边）。改用 `width: max-content; min-width: 100%; margin: 0 auto`。
- **量宽度要量滚动容器**：`.desk-inner` 用了 `max-content` 之后 `clientWidth` 是内容宽，拿它算"适宽"会正反馈（纸越大→容器越宽→纸更大）。适宽/适页一律量 `.desk`。

## 3. 信息归属：一条信息只住一个房间

这是整个界面最硬的一条约束，比任何视觉规范都硬。右栏四个页签 + 纸面 + 浮层，看起来是六个地方，其实是六个**房间**：一条信息住一间，别处只能挂门牌。

| 信息 | 唯一的家 | 别处只能这样出现 |
|---|---|---|
| 原文 / 译文 | 纸面 | — |
| 眉批（九类常用款 + 自造款 + 你自己写的）与引文划线 | 纸面页边，钉在它引的那句话旁 | 问题⑤引用其中「要当心」的那几条；右栏没有第二份列表 |
| 段落角色（八类） | 后台数据，支撑七问与眉批的生成 | 问题②的证据行以"关键证据 / 对照参比"出现一次 |
| 这篇讲什么 | 速览·一眼卡（一句话） | 问题①与④是逐条追问版；一眼卡不复制，只给 ↗ |
| 为什么重要 | 问题① | 一眼卡不重复 |
| 创新点（相对前人新在哪） | 速览一眼卡「创新点」 | — |
| 结论里的数字 | 速览一眼卡的「发现」＋问题④的主张-证据链 | — |
| 作者承认的局限 + 可疑之处 | 问题⑤ | — |
| 原理（为什么成立） | 问题②（综述问领域共识） | — |
| 怎么解决的（实验/手段/改进） | 问题③（综述问组织方式） | — |
| 顺着往下能做什么 | 问题⑥ | 导师三问不复述（提示词里划死边界） |
| 答辩会被问什么 | 速览·导师三问 | — |
| 换个学科怎么看 | 问题⑦ | — |
| 能不能复现（方法） | 速览·方法卡/谱系卡 | 问题③末尾给一个「方法卡 ↗」入口 |
| 图 | 速览·图表速览（缩略图 + 灯箱） | 纸面正文里当然还有原图（那是原文） |
| 术语 / 缩写 | 术语页 | 划词气泡命中术语时给一枚 chip（读的时候要看得见） |
| 问答 | 提问页 | 划词 / 眉批 / 七问上的 ↗ 只把问题送进去 |
| 跨篇对比 | 多选「数据对比」弹窗 | — |
| 从 Zotero 导入 | 长按「拖入 PDF 或点击导入」 | — |
| 阅读进度 | 纸面右缘那根线 + 问题页「读至 ¶n / N」 | — |
| 引用格式 | 顶栏标题旁的「引用」浮层 | 别处不放第二份——它跟标题同族（"这篇是谁"），所以家在标题旁边，任何页签下都够得着 |

**四条推论**（新加 UI 之前先过一遍）：

1. **一个判断只在一个地方展开，别处只给指针或计数。** 一眼卡「发现」右侧的 ↗ 就是这条的形状：发现 → ②。
2. **派生视图不许复制内容。** "同一批文字的第二种排法"不是第二种信息（眉批速览、依据 ¶n 行、段落角色汇总都是这么死的）。判据：删掉它，读者会不会因此少知道一个事实？不会，就只是排法。
3. **跨模块去重靠信息分工，不靠提示词里写"别重复"。** 边界要写进各自的提示词：③＝作者承认的、④＝顺着往下做的、导师三问＝在这之上再狠一层。
4. **算过的进页面就显示（读缓存不花钱），没算过的绝不偷偷算。** 一次模型调用永远是一次用户授权。

新加一块东西之前先问：这条信息有家了吗？**有，就只能加指针；没有，它才是新的一块。**

## 4. 交互七原则

1. **位置即状态**：重开论文恢复上次滚动位置+模式+图层；任何跳转入栈，`Alt+←` 回到迁出点。
2. **动作不打断视线**：段落级操作不额外挂浮件——划选即出气泡，键盘 `t` 直接译当前段（早先的页边 hover 把手与划词重复且追不上鼠标，已删）。
3. **批注即沉淀**：页边承载两种声音——AI 眉批（推断）+ 你的查译/问句（资产）。
4. **姿势跟随任务**：见 §2；不给用户"模式设置"，只给任务入口。
5. **键盘全达，鼠标不强制**：见 §6。
6. **可发现性分级**：默认界面 ≤6 个控件；低频操作收进 ⚙/hover；不加解释文案，行为即说明。
7. **长任务可停**：析读 / 眉批 / 全文翻译都能中途「停止」，已生成的部分保留（翻译已译好的页下次接着译）。

| **引文看全句** | 页边卡里的引文 | 默认两行预览，点「全句」摊开（引文本身点了是跳回纸上那句话——两个动作分开） | 再点「收起」 |

| **速览** | 右栏第二个页签 | 一眼卡 → 图表 → 方法卡/谱系卡 → 导师三问 → 导出；算过的块进页面就显示，没算过才给「获取」 | 点 ↗ 跳对应问题 |
| **确认与输入** | 删会话/分类/文献、改名 | **应用内对话框**（不是系统弹窗）：标题 + 一句后果说明 + 取消/确定，危险动作确定键朱红；可拖走；Esc 与点遮罩取消，Enter 确定 | 取消 |

| **引用格式** | 顶栏标题旁「引用」 | 三组：长条目（GB/T 7714 / APA 7 / Nature 体）· 短引用（作者+年 / 正文括注）· 导入（BibTeX / RIS / DOI）。**点整行即复制**；顶部一行字段核对，认不出的虚着显示 `—`，不猜 | Esc / 点遮罩 |

## 6. 键盘地图（默认隐藏，按 ? 显示）

```
j / k    下一段 / 上一段                     1 / 2 / 3   原文 / 译文 / 双语
t        译当前段并钉页边                    a / m       析读 / AI 眉批
s        划选翻译                            r           框选问 AI
/        聚焦提问框                          x           右栏折叠
g l      文库面板                            Ctrl+F      论文内查找
Alt+←    返回上一个位置                      Esc         收浮层 / 退出框选
?        键盘卡
```

原则：单键优先、左手区为主（右手常在鼠标上）、全部可在 ? 卡里自发现——**零学习成本门槛，上限是全键盘流**。

## 7. 功能过筛

**明确不做**：段内术语悬停提示（textLayer 标注成本高收益低）· **缩论文正文的字号**（PDF 版面固定，缩字让图表和行内标注一起错位；界面字号可调，论文例外）· 分类层级树与保存的检索式（几十篇的体量下是负担，扁平分类 + 搜索足够）· 标签（和分类表达同一件事，只留一种）。

**曾经不做、后来想清楚了的**：**同屏 2–4 篇对照读**——"窗口分裂"反对的是开新窗口丢锚点；同屏窗格共享同一条顶栏与同一套位置记忆，对照读是真实需求。**深色模式**——翻暗的只是界面，纸面永远是白的；暗色的"护眼"与护眼底纹是两件事，两个都在。

新功能过筛的口径：先过 §3 的信息归属（有家吗？），再过人因三问（迁出便宜吗？回来自动吗？沉淀下来了吗？）。

## 8. 字体：两种声音 + 一个署名

排版的核心思想：**每个字体家族只有一种职责**，用户不需要读懂文字就知道这块内容是什么性质。

曾有第四种"人声"字体（楷体）用于眉批，实测偏细偏干瘪、和界面互相打架，**已废**——人味靠颜色、行高和位置表达，不靠换字。中文一律落到系统雅黑，拉丁字母由 Inter 承担。一屏内家族 ≤2。

| 声音 | 家族 | 只用于 | 字号/行高 |
|---|---|---|---|
| 工作声（sans） | Inter Variable + 微软雅黑 | 全部 UI 控件 + 全部内容文本 | 13–14.5px / 1.55–1.7 |
| 编号声（mono） | JetBrains Mono | **只管编号与代码位**：¶号、页码、C1/C2、kbd、百分比、版本号 | 10.5px |
| 品牌声（serif italic） | Fraunces italic | **仅 wordmark 一个词**，别处禁用 | 21px |

**字号阶梯：四档 + 一个 display + 一个「读的一档」，别再加。**

| token | 值 | 只用于 |
|---|---|---|
| `--fs-display` | 21px | 仅 wordmark 与空态标题 |
| `--fs-xl` | 15px | 文档标题、主张、一眼卡主句、弹窗标题 |
| `--fs-md` | 13px | 全部正文与控件 |
| `--fs-sm` | 12px | 次级：证据说明、术语行、提示、开关 |
| `--fs-xs` | 10.5px | 微：标签、¶号、页码、徽标 |
| `--fs-read` | 14.5px | **只给"真的要读进去"的整段话**（七问答案、一眼卡正文、聊天正文） |

`--fs-read` 不是第五级阶梯，它划的是"读"与"操作"的界：判据一句话——这段字是不是要连着读三行以上。**右栏整栏抬一档**（`.rail-right` 内 `--fs-md` 覆写 14px）：右栏是"读"的地方，四档比例不动，不算加档。

**设置里的「字号」（0.93 / 1 / 1.09 / 1.2）**：六个 token 全写成 `calc(基准 * var(--fs-scale))`，设置只往 `<html>` 写这一个变量，一乘全乘。**论文正文天然不动**——pdf.js 按视口比例写死内联 font-size，不认 CSS 变量。原生像素值（色块、¶ 号列、停止键）也一律 `calc(… * var(--fs-scale))`，否则特大档下它们最先裂（实测 `.e-dot` 在 1.2 档溢出 2px）。

小节标签不用"等宽+大写+宽字距"（一屏几十个小灰字抢注意力），改回 600 字重 + 0.04em 字距；等宽只留给编号。实测全界面只剩 5 种字号（原先 17 种）。

**位置规则**：标签一律在内容上方；右栏左对齐、行长 ≤34em；间距走 4px 网格；标题字距 -0.01em，¶号与页数用 `tabular-nums`。

## 9. 配色：纯白的纸

底色就是**纯白**。不做"四层明度"——分层靠发丝线和页面自己的阴影，不靠灰，更不靠黄。

```
桌面 --paper      #FFFFFF
沟槽 --paper-deep #F6F6F5   （左栏、页边批注带——只留一丝）
面板 --card       #FFFFFF   （顶栏、右栏）
内容 --card-2     #FFFFFF   （论文页、卡片、气泡、弹窗）
```

**发暗发黄的历史**：暖黄纸（#EFE8D8）+噪点层像旧纸，亮灰（#F4F2ED）被用户判"看着累"，v4 起纯白、颗粒层删除。**纸的颜色不是风格，是光线**——要暖可以开护眼底纹，那是用户显式选择的开关，不是默认值。纯白底下论文页与桌面同色，靠 `--shadow-page` 浮起来。

### 护眼底纹（设置里切换）

四档：纯白（默认）/ 豆沙绿 `#C7EDCC` / 浅青绿 `#CCE8E8` / 米黄 `#F5F5DC`（经典惯值）。**说清楚：没有任何权威机构认证过"护眼标准 RGB"**，真正管用的是亮度、色温、看远处休息；颜色只是微调，这里是"可选项"不是"药方"。

上色关键设计：**纸面上盖一层 `mix-blend-mode: multiply` 的色膜**，不是整屏蒙版也不是 `filter`——multiply 只乘"底"：白纸乘成护眼色，黑字乘完还是黑字（实测正文对比度 16.9:1，纯白纸是 21:1）。桌面/面板跟换成同色系浅底（桌面更浅，纸才浮得起）；`.page` 加 `isolation: isolate` 把洗色圈在纸内。对比度不是估的：`tools/contrast_check.py` 逐档算。

- **墨色只许三级**：ink `#1D1B17`（正文 17.2:1）/ ink-2 `#55524A`（次级 7.8:1）/ ink-3 `#6B675E`（micro 标签，最差 4.56:1）。禁纯黑。
- **强调色只有一个，是墨色不是金色**：靛青 `#1D4E5F`（深档 `#123A47`）。主按钮、当前态、高亮底、品牌标记。换掉琥珀 `#D08A1C` 的原因：大面积是"屎黄"、白字压上去只有 2.86:1（靛青 9.10）；低饱和+中性色主导+彩色只留一个（60-30-10）是公认最稳的配方。
- **色标只表达一件事：该给多少注意力。** 四档——一个彩色 + 三级灰（人能一眼解码的颜色上限是 3–4 个，八个色相谁也记不住）：

  | 档 | 填充 | 用在哪 |
  |---|---|---|
  | 核心主张 | `#1D4E5F` | 唯一彩色（= 强调色） |
  | 论证主干（证据/缺口） | `#57534A` | 深灰 |
  | 外围与让步（对照/拓展/局限） | `#8E8A80` | 中灰 |
  | 铺垫与流程（背景/标准流程） | `#C9C4BA` | 浅灰 |

  眉批同一套逻辑：值得读（靛青）/ 要当心（朱红）/ 是噪音（浅灰）/ 你自己钉的（深灰）。
- **阴影 = 悬浮 = 暂时的**。静态布局只用发丝线+留白；shadow 只给 popover/modal/拖拽悬停这类"临时浮起"的东西。这是"设计感"的最高纪律。
- **笔触跟着档位走**（否则档位等于没分）：值得读是马克笔（色带+实线）、要当心是波浪线、可跳过只留细点线、自己写的用墨色实线。一个 alpha 承载不了三个档位——`mix-blend-mode: multiply` 让色带压字时字**更实**而不是被洗白。

## 10. 品牌标记：一枚印章

**形状**：椭圆环 + 环内几行字（末行短一截——真实的段末就是短的）。环是纸的边界，字是内容；椭圆环又刚好是蛋的轮廓，名字里的 egg 靠形状带出来，不靠画。

**为什么推翻"画一只蛋"**：字面图标的三个死结——缩到 16px 只剩一坨、会被读成水滴或卡通蛋（上一版真被读成"水滴"）、换产品名就失效。

**几何**：上下两个半椭圆在最宽处相切（上 ry 34 / 下 ry 42，钝端朝上），环内字条按椭圆内接宽度递减，任何一档都不顶到环。**一套基准几何一稿到底**，`EggMark.vue` 自适应，实测 16–128px 都立得住；小尺寸只画三条字条并把环加粗（再小就没有"三条线"这个特征可认了）。

**试过并否掉的方向**：掀盖的蛋（像戴帽子）、实心蛋横切一刀（像贝雷帽）、字条堆成蛋形（像汉堡菜单）、实心蛋挖洞（像贝加圈）。

**节日换装**是唯一的"到日子的临时装扮"：全部收在印章框内、三色不变、不压三条字条，过完日子自己脱下；清明/国庆等庄重日子主动不换。窗口与冲突规则、农历对照表（2026–2030，香港天文台核算）在 `frontend/src/festival.js`，画法纪律在 `EggMark.vue` 注释。

## 11. 小元素巧思（全部服务"批注本"隐喻，克制执行）

1. **眉批划线 = 真的划在字上**：引文对回字符后**逐行**画——跨几行就是几个块，行内划多长就是多长。
2. **析读进度 = 笔画下划线**：一根发丝线自己画过去，旁边 mono 数字"读至 ¶13"随滚动更新。
3. **拖入时印记原地弹跳**（squash & stretch，仅 dragover 态）；**完成时印记滚半圈**（0.68s，底边着地滚）——彩蛋级，只此两处。
4. **highlight 描画**：引文高亮以 scaleX 0→1 从左向右"画"出来（300ms），像被人当场划的。
5. **旁批是钉子不是纸**：展开长批注时下方批注按实测高度整体下让——永远不叠、不裁、不窜出纸张；长正文在卡内滚动（≤240px），卡片高度由渲染后实测决定。
6. **页边宽度是有话才说的**：批注带只在真有批注时占满 184px（实测同一篇论文 156% → 188%），关掉眉批图层一点都不留。空着的页边不是留白，是浪费。
7. **问题先出现，答案点开才看**：七问默认全部收起，行首编号墨色=已作答——一打开就把结论摆出来是替人读完了。答案随首次析读一次备齐（主张-证据链来自骨架，其余六问由模型作答并按篇缓存）；⑥还能做什么从眉批的「有坑」长出来，眉批重写后跟着重取。
8. **阅读进度是一根发丝**：贴书桌右缘 3px 细线，读到哪长到哪，不写字不报数。

其余一律不加装饰——**一屏最多一个惊喜**。

## 12. 动效：丝滑的纪律

丝滑不是动画多，是**短、少、有物理感、零跳变**，而且**不花哨**。

### 三条硬规矩

1. **退场永远比入场快**：入场 200ms（淡入+上浮 4px），退场 120ms（只淡出）。
2. **入场用 keyframes，退场用 transition**。transition 的起点类要靠 rAF 摘掉，rAF 被节流时元素会卡在全透明——**内容绝不能挂在可能跑不动的过渡上**。`.pop-enter-active` 是 `animation: popIn`（声明式跑完不依赖 JS），退场才用 transition（Vue 有定时器兜底）。
3. **绝不为动效牺牲内容可见性**：换模式不遮论文，只在书桌顶部点一条 2px 细进度线，不搞盖住内容的加载器。

### 「东西从哪来」比动效本身重要

- 弹层从**触发它的那个点**长出来，位移只有 4px，不从屏幕外飞进来。
- 旁批被推开时**滑过去**（`transition: top 260ms`），不是瞬移。
- 分段控件是**滑块**：选中块自己滑过去（200ms spring），三按钮强制等宽。

### 最重要的一条：别让读者的视线跳走

任何重新排版的操作——换三态、切对开/交替、折叠右栏、缩放——都**必须落回原处**。实现：以「原文第几页 + 页内高度比例」为锚点（三种模式的页号不是一回事，统一换算），落位后**量一次核对**，偏了再落（最多四五拍收敛）——落位要跟渲染、栏宽动画、重定标一堆异步赛跑，赌一次成功是赌不赢的。用户一旦自己滚动，立刻停止追位。

**跳转要落到行，不要落到段**：读者点一条眉批是想看"这句话"。落点=引文首行，落位后实测坐标回算一次。远距离跳（翻页、跳页）一律即时，不要"平滑滚两秒"。

### 缓动与时长 token

```css
--ease-out:   cubic-bezier(.25, 1, .3, 1);      /* 出场：淡入 + 上浮 4px */
--ease-spring:cubic-bezier(.34, 1.4, .44, 1);   /* 轻弹性：滑块、toast */
--ease-smooth:cubic-bezier(.4, 0, .2, 1);       /* 通用状态：颜色/边框 */
--t-fast: 120ms;   /* hover、退场 */
--t-base: 200ms;   /* 入场、气泡、滑块 */
--t-slow: 320ms;   /* 浮出面板、栏折叠 */
```

一切过渡 ≤320ms。**不花哨**：按钮不做悬浮上浮（位移是"网页感"的源头），hover 只换背景色；缩略图 hover 只放大 2%；全局尊重 `prefers-reduced-motion`。

### 动效清单（全量，此外不加）

| 场景 | 动效 |
|---|---|
| 所有弹层 | 入场 popIn 200ms（淡入+上浮4px+微缩），退场 120ms 淡出 |
| 遮罩、整页切换 | 纯淡入 200ms / 淡出 120ms |
| 换三态 | 内容直接换，**位置按锚点落回**，顶部一条细进度线 |
| 折叠右栏 / 缩放 / 拖栏宽 | 重新定标后落回原处；拖的过程中不重排，松手才排一次 |
| 打开已有眉批的论文 | 划线与批注卡"画"进来一次（300ms），只在打开/切篇时一次 |
| 阅读进度线 | 高度跟随滚动，200ms 缓动——不是每帧硬跟 |
| 眉批生成完成 | 批注卡 stagger 入场 + 引文描画 |
| 回答流式输出 | 逐字出现 + 1s 步进光标；正文不做入场动画（一边流一边重排会把字推来推去） |
| 拖入 PDF 悬停空态 | 印记原地弹跳（仅 dragover 态）；析读/翻译完成滚半圈 |
| 跳转 | smooth scroll + 目标描边渐隐（远距离除外，见上） |
| toast | 底部上浮 + 淡入，退出更快 |
| 浮窗拖拽 | 位移跟手不动画；拖动时关掉自身过渡，松手即定 |
| 阅读器控件条 | 平时半透（整条 72% 不透明，正文透出），hover/拖动变实心 |
| **打开一篇论文：破壳 → 纸面** | 桌上只有三样东西：印章（缩放淡入 420ms）、一条细进度线、一个词"正在破壳"。进度线先按真进度走，本地 PDF 瞬时就绪所以另有缓慢逼近的底速（每 240ms 往 92% 挪，上限 90%）——有真进度用真的，没有也让线一直往前挪，否则"在等"和"卡死了"长得一模一样。进画：破壳淡出 90ms → 纸面淡入并轻轻落下 6px（240ms）——像把纸放上桌，不是弹出窗口 |

### 性能纪律

只动 `opacity`/`transform`；滚动跟随用 IntersectionObserver 不挂 scroll handler；canvas 重渲染去抖 160ms；`will-change` 只加在已知将动的浮层上。

## 13. 文案：标签，不是说明

界面上不写解释设计的话。规则：

- **写"它是什么"，不写"它意味着什么"**。`方法卡` ✓ / `方法卡 · PROTOCOL` ✗。
- **说人话，不摆黑话**。`GAP`、`CLAIMS → EVIDENCE`、`SEED` 这类圈内术语在界面上是门槛，直接写"研究缺口""论点与证据"。
- **不写"你可以做 X"**。`展开全部 8 步` 比 `点击这里可以展开全部 8 步` 好——控件本身就是那句话。
- **不重复别处已有的信息**；真有用的计数并进那条读数里写。
- **不写"只存本机"式的自我表扬**。承诺要出现在用户会怀疑的那一刻，不是每一行。
- **唯一的例外：隐性交互的操作指引**（虚线框"拖入 PDF"、框选态的常驻退出按钮）——没有它功能就不可发现；但指引也不许写成说明，"框选 [退出]"就够了。
- 判据一句话：**删掉之后，用户会不会因此少知道一个事实或找不到一个功能？** 会，就留；不会，就是说明，删。

## 14. 浮窗都能拖走

设置弹窗、应用内对话框、快捷键卡、划词/框选气泡、图表灯箱、阅读器控件条——**按住就能拖**（`v-drag` 指令）。三条约定：

1. **位移写在 `transform` 上**，不改 `left/top`（改了会把各自那套定位弄乱）。
2. **拖完那一下不算点击**：位移 >4px 吞掉随之而来的 click（弹窗被拖到遮罩上松手时，click 的 target 还是遮罩，父元素也要吞）。
3. **至少留 48×40 在视口里**，拖不出屏幕找不到。（带 `key` 的控件条把位置记进 localStorage。）

**状态型浮层必须有 ≥2 条独立退出路径，其中之一不依赖鼠标事件本身。** 拖拽悬停浮层是最典型的反面教材：只看 `dragenter`/`dragleave`，松手落在窗口外、窗口失焦、drop 被 `stop` 掉时没有任何事件来复位。凡是"跟随某个瞬时状态亮起来的浮层"，都要假设那个状态的通知可能永远不到，另挂 `dragend`/`blur`/`Esc` 兜底。同理：不要在有全局 `drop` 处理的地方给子元素挂 `@drop.stop`——会顺手拦掉 `preventDefault`，拖一个文件进来整个应用就被导航冲掉。

## 15. 提问面板：照 DeepSeek / 豆包网页版的样子做

好用的原因是四条，不是皮肤：

1. **回答逐字吐出来，中途能停**。停下来的半截**留着**（那是用户已经读到的东西）。
2. **一摊对话一个上下文**，「新对话」是一等公民，不是"清空历史"。
3. **每条消息底下有一排动作**（复制、重新生成、删除），悬停才出现。
4. **输入框会长高**，Enter 发送、Shift+Enter 换行，`isComposing` 时 Enter 不发送（中文输入法选字误发是最烦的一类 bug）。

取舍：用户消息靠右一个小气泡（深浅对比只靠这一个小色块）；引用来源是可点的 ¶ 号；落库 id 顺着流回传，"删除这条"删的是真行（用户中途停止时由前端落库拿回 id——不这么做，"删除"接的是屏幕上的幻影，实测过删掉刷新又回来）；会话标题取第一个问题；**扫描件直接说清楚"能读原文、能框选问图"**，不让模型对着空上下文编。

## 16. 验收清单（发布前过一遍）

a) 一屏内字号 ≤5（含 display）、等宽只出现在编号位；b) 静态区域无阴影；c) 所有交互动效 ≤320ms 且缓动来自 token；d) `prefers-reduced-motion` 下无动画；e) 60fps 目检（栏折叠、眉批划线、气泡）；f) 每条浮层都有 ≥2 条肉眼可见的退出口，其中之一不依赖鼠标事件，且没有任何浮层被滚动容器裁切；g) 界面文案里搜不到"你可以""表示""也就是"这类解释句。

其余实测踩出来的判据：

- **聚焦别用默认 `focus()`**：查找框挂在书桌内容末尾，浏览器为"把焦点滚进视野"会把整个书桌滚到底，冲掉刚跳好的位置（实测偏移 2400px）。一律 `focus({ preventScroll: true })`。
- **缩放分清"缩论文"和"缩界面"**：`Ctrl+±` 是浏览器缩放，`Ctrl+滚轮` 只缩这张纸；落点锚在光标底下那一行（记录页内比例，缩完重算落回，实测漂移 0）。
- **"截断"要看有没有出口**：无出口的硬切都是错的（`-webkit-line-clamp`、`nowrap+ellipsis` 都栽过）；高频浮层里"两行预览 + 明确出口"是好的。两个动作不要挤在一个点击上。
- **归一化匹配会吃掉空格**：引文对回原文时跨空格拿到两个矩形，中间开洞——修法是**合并**（同行内缝小于一个字高就接上，行间断开不管）。精确不是"多画几段"，是"该连的地方连上"。
- **hover 高亮不能用 `currentColor`**：那会把"这是哪种批注"的颜色信息抹掉。
- **"拿得走"的界面**：整条可见、点哪复制哪、缺的字段明着缺——能带走的必须是完整的、可核对的那一份，残缺要看得见。
- **在等的看得见、在跑的不被打断**：见 §12/§15；凡是等外部响应的地方都要有一行在动的东西。
